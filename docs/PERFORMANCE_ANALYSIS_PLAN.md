# 性能数据采集与分析执行计划 V3

日期：2026-10-28。协议：`timing-v3`。替代 [V2.1](TIMING_CAPTURE_PLAN_V2.md)，旧数据及其协议不变。正式矩阵的数量与预算以 [机器可读协议](performance/protocol-v3.json) 为准，本文规定含义与执行规则。

本轮交付是可冻结的计划、数据契约和审阅记录，不是性能测试结果。**文档准入 D**表示可以按本计划实现工具并做小规模演练；**实测准入 P**表示该环境已经用真实产物证明工具、分析与开销合格，才允许正式批量采集。两者分别记录，不能把 P 尚未执行写成验证失败，也不能以 D 通过代替 P。当前状态见 [准入审阅](PERFORMANCE_PLAN_REVIEW.md)。

当前只用既有 IDEA 内嵌模拟器、独立验收目标和 R8 优化包。来源固定京东 `OPTIONS https://api.m.jd.com` 的响应头，不打开京东业务页面，不测试真实账户。其他来源、多设备、光学测量、真实业务接收、超过一小时等待及休眠后继续点击不在本轮结论范围内。屏幕关闭、服务断开和停止必须取消任务；不恢复旧点击。

50 ms 是严格样本要求，不用 P95 代替；完成分析可以得出“不达标”或“参考不足，无法确认”。真机比较独立安排，不在当前范围内，也不以模拟器得出物理极限。[S2][S3]

| S9/S10 | 跨时基需要 clock snapshot；文件流式写出也可能丢失，DISCARD 也会丢新数据 | 每段校验映射、序号和 stats；长时轨迹流式写出，不能把没有环形覆盖当作无损 |

| S12 | 标准授时协议有多个收发时间戳来估计延迟和偏移 | 单个 HTTP 请求 ID 只作条件参考，独立实现不等于独立时间标准，不自动改用 NTP 或最小 RTT |

## 3. 版本、环境与数据契约

### 3.1 不可覆盖的身份

每个 run 先创建新目录 `.tools/timing-v3/<runId>/`，存在即拒绝。manifest 固定协议、源文件 SHA-256 清单、实际两个 APK 及 mapping、驱动/分析器/Trace Processor 版本与 hash、全部配置、预定矩阵/随机种子、时区、模拟器 boot/serial、OS/ABI、显示刷新率/密度/渲染器、宿主 CPU/GPU/虚拟化及电源状态。固定种子 20261028，保存一次生成的完整顺序，不反复抽签。不能用后来的 APK 补旧轮次。

JDK 17、Wrapper 和已有 D/E 盘缓存；不添加生产依赖。工具实现和打点的变化先完成测试，再冻结两个APK；采集期间生产调度、绘制、授时及点按长度不变。安装后将两个测试APK固定为speed编译并保存实际dex状态及操作结果，不能支持时P不通过，不能混用编译模式。有warmupTasks的组在该组会话开始统一以4000ms提前量执行10次短任务预热，批次间进程未变可复用；预热记录单列，不计正式样本，G/W长也不把半小时/一小时当预热提前量。A0为零预热的进程首任务，不指设备/安装冷态；H按受控配置准备，不借预热触发故障。时钟组就绪后固定10秒稳定等待再开始观察，过程也记录。不能在模拟器/宿主上并行构建、跑其他测试或启动第二台模拟器。

### 3.2 必需字段

所有事件共同包含 `schemaVersion/runId/groupId/batchId/attemptId/processBootId/pid/tid/sequence/eventName/elapsedNs/clockId`。无任务的时钟/资源记录 attemptId=null，带独立 recordId；字段不适用须 reason，不填 0。二进制原始记录可定长，离线转换为 JSONL；进程只保留有界缓冲与计数，原始数据全量流式保存。

## 4. 时基、指标和参考假设

主链为同 boot 的 `elapsedRealtimeNanos`；epoch 只用于用户目标/授时/字符。MotionEvent uptime 与接收入口 elapsed 分开。每次快照取 5 组 elapsed→uptime→elapsed 的最窄包围，包围 ≤0.5 ms，含毫秒量化的转换不确定度 ≤1.5 ms；trace 已知标记的映射残差 ≤1 ms。失败影响对应转换指标，不抹掉仍有效的同 elapsed 原始数据。宿主/设备只以心跳双端包围区间关联，不能直接相减。[S1][S9]

设用户目标 epoch 为 T、最终本地截止为 D，目标入口为 m，单位统一为 ms：

- 本地迟到 `L(m)=m−D`，分别算 dispatch、DOWN、onClick，保留提前的负值。
- 独立来源估计 `R(m)`，总误差 `E(m)=R(m)−T`；截止映射偏差 `R(D)−T` 单列。同一单位斜率参考下 E 可拆为映射偏差与 L；不同参考分段计算，不相加分位数。
- 绘制滞后：观察时当前任务/来源参考减最近已绘制字符；绘制外部误差：该字符减观察时 R，二者不等价。
- 呈现误差：观察时最近已实际呈现的时钟帧字符减 R；另报告 read→draw→submit→present 与持有该帧的年龄。

### 4.1 HTTP 参考的可判定范围

独立 worker 使用相同 API，不共享应用连接/缓存/锚点，不换源、不改产品请求。完整调用边界 s/r、服务时间 S，中点 M=(s+r)/2。以“时间戳在请求期间生成，短窗口内来源与 elapsed 等速”为显式模型，`R(m)=S+(m−M)`；网络/量化/对齐区间至少包含 RTT/2、1 ms 的时间戳量化预算及映射误差，另列实际外推年龄。连接后边界不能替代完整请求边界。未知来源语义、系统偏差或速率误差不声称已经包含在这个区间。[S12]

S的可重放解析固定为：HTTP头名不区分大小写，从原始多值头取得x-api-request-id；相同值折叠，多个冲突值拒绝。去除首尾ASCII空白后，整串匹配`^[0-9]+-[0-9]+-([0-9]{13})$`；捕获第三段，以十进制有符号64位整数解释为Unix epoch毫秒，不换算为秒。S须在[946684800000,4102444800000)（2000至2100年）内；HTTP非2xx、冲突头值、Age>0、格式/溢出/范围失败均有独立reason，原始头保留。Age缺失按未提供记录，不证明无缓存；Age非法则参考无效。Date只作辅助，不补齐毫秒真值。合法fixture为`10105444978-107668-1792980614483 → 1792980614483ms`；缺头、少段、10位秒值、字母尾缀、冲突多值和超范围必须拒绝。独立worker和离线分析均使用这份协议测试fixture，而非读取产品锚点；产品若采用不同有效性规则，差异如实记录，不在采集中改生产解析器。

默认外推到接收入口最多 5 秒。前后请求分别算估计，不挑最小 RTT，不平均掉不相容；原始估计全部保留。对独立前后参考区间冲突、来源跳变、缓存/头格式异常或超龄，标相应原因。没有可证明速率误差上限时，所有总误差结论均标 `modelConditional=true`，不能获得无条件时间认证；增加 HTTP 样本不能消除该限制。

每个点击入口先分别用选定的前、后样本得到区间I前/I后。任务级参考要求两边都有效且各自外推年龄≤5秒；缺一边则保留单边诊断估计，任务为not_evaluable。两区间不相交则为reference_conflict，不以平均或交集掩盖差异；相交时取保守包络`[min(两下界),max(两上界)]`作该入口唯一判定区间，各自原始区间仍保存。一个within、另一个inconclusive不会通过。三个入口都within才是该任务来源总误差通过；任一确定outside记性能不通过，其余只要有inconclusive/not_evaluable就不能宣称任务通过，原因逐项列出。

点击允许区间 [0,50]，显示允许区间 [−50,50]。估计区间完整位于允许区间记 conditional_within，完全在允许区间外记 conditional_outside，部分相交记 inconclusive。若模型前提未建立或参考缺失为 not_evaluable。点估计越线数也保留，但不冒充确定越线。参考区间宽度 >50 ms 的点击样本不能被判为 within；这是可判定能力的限制，不自动成为产品迟到。

准入先以20个任务级配对演练（各一前一后，共40个计划独立请求，提前量4000ms）报告有效率、包络区间宽度和可判定率。若有效配对不足18/20，停止来源组，先修工具或确认环境；若没有任何样本具备宽度≤50ms的包络区间，只能先输出“当前方法无法裁定50ms”，不启动R/G的数小时正式任务。允许区间够窄也不保证实际点击会通过。此门槛只控制采集可用性，不挑选正式数据；正式来源失败均留在计划分母内。

## 5. 频率、时钟画面与长时呈现

本地观察按开始时间的绝对 1 秒网格，持续 d 秒有 d+1 个计划点；数据源对照按独立请求计划点计数。E 的外部间隔 1 秒、F/G 的周期外部间隔 30 秒。**F 的 3601 个本地观察与 121 个外部对照是两个分母**；每个外部请求以驱动取得响应头的同一单调时刻 q 为观察点，离线匹配 q 之前最后绘制/呈现帧，而不是等待下一次逐秒 app 回调。要求 q 距 M ≤5 秒，否则该外部点无法评价。中间逐秒值只分析本地画面年龄和锚点，不用 30 秒外插填出外部真值。

驱动独立 worker 按绝对网格记录计划/实际观察时刻，不每秒调用 UI Provider；app 只记录实际 draw、参考选择/生命周期与任务事件，离线匹配观察时刻之前的完整事件。主线程阻塞期间没有新 draw 就仍取旧帧，不能用恢复后新帧回填；参考状态事件不足时标未知。驱动自身错过网格记录实际时间/缺失，各网格超时不追赶补发。资源、外部请求与独立心跳不调用 app UI，不以驱动线程存活代替服务连接。

R/G/W 的事件参考探针：在计算并持久化用户目标T、尚未操作滚轮/播放时，以同一来源快照求投影截止D0，预注册D0−3000ms的前请求，必须在D0−1000ms前完成。独立worker可在滚轮设置期间或播放前执行；1800ms短提前量不能等arm之后才安排一个已经过去的探针。后请求在实际关键区结束后立即发起。arm/重校时后保留最初探针计划，不追发；冻结截止时保存D0、arm截止与最终D，分析时检验探针对最终接收的年龄/包围条件。G/W长周期参考若在冻结附近更合适，也全部保留并按固定规则取距离入口最近的合格前、后样本，距离相同取先计划者，不能按误差或RTT选。请求最小间隔1秒；冲突优先事件探针、周期点记被抑制及所复用sampleId。后台产品授时请求不受此限制。

### 5.1 字符到呈现的具体关联

benchmark 的 ClockFace 使用静态 trace 标签的 onDraw slice、数字 drawId/epoch counter 和二进制帧记录；在 readTime 后立即记值，不创建每帧字符串、不改变刷新调度。将 draw slice 关联到同线程包含它的 doFrame，再通过渲染 flow/token 及明确的时钟 surface/layer 关联应用帧，沿 flow 关联 SurfaceFlinger 显示帧。以显示帧实际结束及 present 状态判断呈现，不能用 expected 时间或应用 Actual Timeline 的末尾代替。[S8]

多个 draw 合入一帧时取该缓冲实际提交的最后内容；多个 surface 候选、缺 token/flow、未提交或未呈现时必须标明。trace 中没有唯一关联证据时不能以“时间最接近”猜测成功。准入要演示一次正常、一次重绘合并和一次被延后/未呈现帧，并离线重放取得相同关联结果。相关 API/trace schema 按当前设备探测记录，不假设普通 overlay 的 View 拥有 Activity Window。

P短验证后执行 **P长整段 60 分钟呈现组**：只开 FrameTimeline、两个 app 的帧关联标签、进程身份/时钟包和必要 gfx 关联，不开全系统 sched 或 CPU 栈；流式保存全部帧与关联记录，无缝覆盖全程和首尾。逐秒观察 3601 点，外部对照 121 点；实际呈现误差分别对本地/外部观察点报告，不能把 121 个外部点扩展成 3601 个外部精度认证。F 无 trace、P长有 trace，条件分开，P长的表现不能替 F 宣称同一无采样场景已经通过。

若 P 的关联能力或整段流式预算不过，P 实测准入失败，不开始 P长；不能采完 F 才决定放弃呈现。此结果不阻止已有局部事实，但本轮完整目标保留未完成，不自动缩小为“只测绘制”。FrameTimeline 软件呈现也不认证物理像素发光时刻。

运行栈 C 采用 SW_CPU_CLOCK；W 的调度事件采样与运行栈分开标记。W 过滤经过身份验证的 app/目标主线程和 RenderThread 的 TID：sched_switch 的 prev_pid/next_pid，sched_waking 的目标 pid；仍保存唤醒者身份，进程退出即停止并重建新批。每个事件全系统展开栈被禁止。内核支持/过滤准确性必须在 P 门槛验证，权限不足不关闭安全策略，不能把 W 偷换为普通 49 Hz。[S5][S7]

G 长等待每次列出全部同步/采纳、旧新截止/代次、最后参考年龄、5秒锁定、准备和 DOWN/onClick；要求至少一次有效重校时、旧回调失效及临界锁定才叫完整路径覆盖。没发生就明确未覆盖并保留试次，不偷偷续跑至覆盖。F/P长是空闲浮窗；G/W长是等待中的任务，互不替代。

## 7. 公开操作、停止、超时与原始现场

公开流程为开启浮窗/准星→定位→四列滚轮确认目标→明确播放一次；prepareTimed 等内部捷径只限工具受控验证，不得替代正式组。播放基准固定为驱动开始公开控件操作，方式固定为同一种 UI 自动操作，记录开始/返回/接受/实际 arm。计划提前量和实际 arm 剩余时间分列。

稳态目标=Tnow+设置裕量3000ms+计划提前量，冷界面裕量10000ms；准入若发现不足，修订工具或统一预算后重新冻结，正式阶段不因失败增加裕量。设置前持久化试次与计划请求；设置期间依然允许独立 worker 执行预注册参考探针。超期记录前置失败，不静默选明天/重设目标。保存最终 epoch、时区和今天/明天选择，跨午夜不靠时分秒字符串猜日期。

点击关键区起于最终准备前500ms（正常约D−750ms），止于引擎和目标都收尾后500ms；未收到以D+3000ms接收超时及停止收尾。禁止额外UI遍历、Provider状态请求、截图、PSS、主动外部参考请求和 app/驱动同步落盘。自然授时、系统 trace 后台流式写和独立控制心跳保留，均计入开销；不暂停真实负载取得好成绩。临界重校时改变 D 使已发生操作进入实际关键区时，记录干扰并标该指标质量受影响，不能追溯删除操作。

固定上限：界面准备15000ms、播放返回3000ms、目标回执至最终D+3000ms、停止确认2000ms、清理后安静1000ms。若尚未冻结D，宿主安全外层截止取 arm 时D+允许校正1000ms×ceil(等待/60000ms)+10000ms；产品更新越界/来源变化按原规则停止，外层预算不延长产品期限。长等待不适用“几秒无回执”超时，仍每秒心跳。独立宿主每500ms监督控制通道，设备驱动连续5秒收不到心跳停止本批，不靠 app UI 实现停止。

每次终态先写原始状态、原因、elapsed时间及回执结局到预分配内存，再执行停止/清理；后续窗口/截图另记起止，不能覆盖原事件。失败分类：播放未发现/未接受、前置已过期、arm后过期、准备失败、拒绝、取消、超时、断开、完成但未接收、重复/错点、采集器故障、归属未知。系统回调成功和目标接收不必同时发生。

产品迟到/过期但能确认任务已结束、无待派发和未闭合触摸时，可以进入预定的下一个独立试次；这不是补点或重试。归属不明、清理超时、ANR/进程死亡或用户停止就终止本批，其余明确未执行；仅在授权测试范围内可终止受测应用，不重启模拟器或操作其他应用。新批须重新检查连接/版本/质量，不恢复旧任务；已注入手势不能保证撤回。

计划台账逐条持久化；每进程2MiB有界事件缓冲，关键区外增量落盘，序号/累计写入/flush watermark可审计。长时组至少每10秒有一次刷盘机会；若阻塞或关键区推迟超过30秒，记录故障并停止新增任务，不环形覆盖。帧流可持续记录，但不能用每帧字符串或无界列表。进程崩溃导致的尾部未落盘须标未知，不伪称完整原子现场。

## 10. 轨迹、空间、时间和恢复预算

短诊断采用180秒/128MiB硬上限、DISCARD并保留stats；规划有效占用≤90秒/64MiB。CPU49Hz与事件过滤参数固定，禁止全系统syscall/堆分配/全事件栈。pilot若表明10次一批超过预算，按`floor(min(90s/每试次P95时长,64MiB/每试次P95字节))`算批容量；结果小于1则该模式准入失败，不能把超限单任务强行设为1。正式开始前一次性冻结分批表，总计划量不变。W长为单任务独立预算：360秒/512MiB硬上限、180秒/256MiB规划限额，按第6节累计校正上界与pilot写入峰值证明可容纳；不在一小时内持续开CPU栈。

P长帧专用轨迹硬上限3630秒/8GiB，中心buffer64MiB、流式写周期5000ms，DISCARD和incremental state/clock包保留；pilot验证峰值速率×最坏写出间隔≤32MiB、预计全段文件≤4GiB。没有开全系统调度或CPU栈不代表必然低扰动，仍须通过P。达到大小上限提前停止、丢弃或缺尾标质量失败，不把短文件冒充一小时；不以重开trace制造未记录缝隙。[S10]

设备/宿主在开始前可用空间分别至少 `max(2×本轮预计本地最大驻留,10GiB)`，资源不足不开始；每批归档校验hash后才能按manifest规则清理已转移的设备副本，宿主原始文件不删除。长时文件流式下载/落盘的影响列入开销，保留flush与copy时间。

全部固定等待：G约4小时46分20秒、W长约1小时31分38秒、F/P长合计2小时；另含短任务、界面设置、清理、探针与演练。初估整体14～22小时/环境，**不是固定承诺**。pilot必须生成逐组最坏时长与请求数清单：短任务每次至多15+3+提前量+3+2+1秒；资源/外部失败不忙等；G/W长用第7节外层截止。总预算不足时只报告未完成，不删组后称完成。

控制心跳和500ms监督不可因关键区延迟，始终在独立通道/线程运行且纳入开销；只有宿主资源采样和设备30秒资源可延迟到关键区外。每条有计划/实际区间与缺失原因，不能补造不存在的资源。测试亮屏/保持唤醒的既有设备设置先备份，只在模拟器测试范围内使用；未保持亮屏则记录取消，不改产品增加唤醒权限。不得重启IDEA内嵌模拟器、改渲染模式、Root或关闭安全限制来改善数字。

结束后停止新任务、确认无未闭合输入/活动trace，恢复普通Debug与原偏好/系统设置、移除测试组件，保留内嵌设备。恢复脚本失败须明确保留待办，不能写恢复成功。普通构建无测量端点；工具改动运行对应测试与项目规定检查，保持JDK17和非C盘Gradle缓存；文档阶段只检查文档，不声称构建通过。

## 11. 离线性能分析步骤

1. **完整性**：验证manifest/hash/协议/boot/时基、文件截断、事件序号/flush、全部trace stats；缺失按指标标质量，不对未知填0。计划=已尝试+未执行；尝试从第一个准备动作开始。
2. **结局**：任务接收互斥为零次、恰好一次正确目标、重复/错点、未知；另有引擎终态、性能判定、采集质量三个独立维度。未接收/尝试、正确一次/计划、引擎失败/尝试、未执行/计划分列，不重复相加失败率。
3. **本地链路**：每组计算dispatch/DOWN/onClick的有符号迟到，拆回调排队、内部执行、系统到DOWN、DOWN→UP、UP→onClick；定位最初变慢阶段。系统完成回调单独画，不强行串行或加到点击延迟。
4. **外部参考**：按原始请求重建模型参考、时间年龄/区间和总误差；区分参考映射偏差、实际本地迟到及未知来源偏差。输出raw estimate、conditional interval、判定与原因。
5. **长期漂移**：F/G/P长分别画参考残差、画面年龄、每次同步修正/来源年龄/锁定及前后10分钟段。按每段实际时间拟合残差斜率ms/hour，来源跳变另计，不跨校正跳变做一条回归；网络噪声大时只报观测趋势，不冒充振荡器精确ppm。
6. **呈现**：对每个已关联帧分解draw/submit/present，观察点取此前最后已呈现时钟帧；误差与帧持有年龄分列。丢帧、关联歧义和未呈现计数保留。
7. **归因**：为所有>50ms、提前、失败、参考冲突列清单；每类最慢10条及所有失败逐条链接原始现场。B/C/W同窗口核对running/runnable/blocked、唤醒者、GC/Binder/渲染及对应事件栈；缺证据的A/G只标未知。guest Running与宿主同期高负载只支持相关，不证明物理CPU/GPU瓶颈。
8. **资源与候选优化**：给两进程＋驱动的CPU/PSS/线程/FD趋势，标资源空档、GC与关键区重叠。D一次只改一项；固定任务引擎与来源，差值不跨组拼凑。PSS增长不等于泄漏，heap dump只在后续明确假设下另开诊断，不插入本轮时间基准。
9. **报告**：按第12节拆分状态和可证明范围，列代码可改、平台/目标贡献、未知项与最小后续实验。新假设才允许补采建议，必须指出旧数据具体缺什么，不以“想得到更好P99”为由重跑。

统计统一最近秩P50/P95/P99、最大/最小、>50ms和提前数；每组和每批都给n、原始失败和缺失分母。按冷/稳态、提前量、trace/探针模式、参考年龄[0,5)/[5,30)/[30,60)/[60,+∞)秒、是否重算、方向/幅度、同步重叠、每10分钟段拆分。首批首任务不自动等于冷启动。3个长等待值逐个展示，不声称稳定P99；顺序/共享参考不假设独立，不提供没有模型依据的独立样本置信区间。

图表至少含阶段分布与ECDF、逐次迟到/参考年龄时间线、同步校正与长期趋势、帧绘制到呈现时间线、PSS/CPU序列、异常因果时间线；C的运行火焰图与W事件栈分开。每一图能回到group/batch/attempt/frame/sampleId和原始文件，图表颜色不替代证据强度。

## 12. 完成标准与停止补采规则

验收集合固定：本地正常点击为A0/A1/A2/R1/R2/G1/G2/G3/G4；来源总误差为R1/R2/G1/G2/G3/G4；绘制为E/F；呈现为P短/P长。B/C/W为诊断、D为隔离对照、H为受控故障，均不纳入正常性能总体，D0也不例外。机器协议的`acceptanceGroups`必须与此一致，不允许分析时自行增删；整体通过逐一检查这四个集合及长等待路径覆盖。

| 状态 | 可以认定的条件 |
| --- | --- |
| D 文档执行准入通过 | Q1～Q7均有数据/组/方法/判定，矩阵预算一致，所有已知矛盾有决定，来源可查，独立读者无未处理阻断项；可进入工具实现和P演练 |
| P 实测准入通过 | 第8～10节对应能力、完整离线演练和实测预算有真实证据；未执行不能勾选；通过后才可正式批量采集 |
| 采集完整 | 全部预注册试次/观察点都已执行或按预定故障规则记录有效终结，原始证据可重放；合法网络失败、产品过期/丢点/超限可以作为完整负结果。采集器缺字段/丢失/未执行导致覆盖缺口时仅为部分完成 |
| 性能分析完成 | 对已执行场景完成第11节报告，未知/无法确认有具体原因。产品不达标仍可完成分析，不为让结果通过无限补采 |
| 本地50ms通过 | 正常点击组所有计划任务正确接收一次且dispatch/DOWN/onClick均在[0,50]ms，无失败/提前/缺失/未执行；诊断/故障组不能替代 |

| 绘制/呈现50ms通过 | E/F绘制与P短/P长呈现分别对其预定外部点满足区间[−50,50]ms，无无法确认/缺失；本地逐秒年龄单列。P长通过不能冒充F无采样表现；观测点达标不覆盖每一瞬间 |

完整负结果与采集缺陷必须区分。例如目标准时前置但实际onClick晚100ms，且事件齐全，是有效超限样本；API成功但区间宽导致无法裁定，是有效的参考能力负结果；没有记录DOWN入口或trace提前截断，则对应指标是采集缺陷。后者也保留，不能自动替换原名额。长等待未发生有效重校时是路径未覆盖，不是工具自动补跑的授权。

正式阶段只在质量/停止规则触发时中止，不在看到一次性能失败后重置整组；质量错误若修复，增加protocol/run关系及新组，保留旧全部数据。完整原始数据已足以支持当前范围内的结论时停止采集；想回答新的设备/场景/UTC问题须明确新目标。任何方案都不能保证随机异常一次出现且可完全归因，本计划保证已知问题有事先安排的证据路径和明确的无法确认出口。

交付包括原始文件及SHA-256索引、冻结协议、能力/开销/恢复报告、质量与任务台账、SQL/分析器及测试结果、统计表/图/火焰图和结论。大文件只在忽略目录归档，文档与索引可提交，不提交SDK/构建缓存/本机路径/偏好/签名密钥。本轮不自动提交或推送。

## 13. 文档与实测准入的执行顺序

1. 当前Goal：核查官方资料→确定数据与协议→静态一致性检查→独立读者反例审阅→修正→记录D结果。只改文档与协议，不连接设备采样。
2. D通过后：实现缺失打点、驱动和离线分析，按TDD验证第8节数据/故障用例；现有timing-acceptance脚本不自动视为已支持V3。
3. 小规模P演练：核实能力/干扰/预算，输出真实文件和离线报告；不以测试fixture或旧轮次证据充当新P证据。
4. P全通过：冻结实际run manifest，执行正式矩阵；每批质量检查，短组完成且报告链可重放后才进入小时组。
5. 采集/分析/恢复分别验收。P未过不能宣称正式可采，D已过也不应再被表述为“计划尚未完整”。
