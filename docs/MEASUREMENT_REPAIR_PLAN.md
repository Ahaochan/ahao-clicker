# 测量修复与单变量优化

日期：2026-10-28。用户本次授权修复帧解析/关联/时基，实测打点开销，随后优化绘制和点击关键路径。该授权允许生产候选实验；此前“仅分析”的限制不再适用于本任务。只用现有模拟器，不重启、不换渲染器，固定 JDK17、Wrapper 和非 C 盘缓存。

本轮是针对已定位问题的修复和优化实验，独立于冻结 V3 的 27 组正式验收。原 V3 的 2880 次点击、来源绝对误差及小时级验收状态不被本轮替代。相对本地截止的真实目标接收用于优化比较；京东参考精度不足仍作为绝对误差限制保留。

## 顺序与准入

1. 保存本轮开始时源码、普通 APK、偏好与设备设置。旧轨迹只读，离线定位全部帧错误到原始字段/记录；新增测试先失败，再修解析/关联。辅助元数据无效与结构/时间线损坏分开，所有原始计数保留，不能隐藏错误。
2. 唯一窗口身份＋精确 surface/display token 关联；处理 Choreographer resync 的实际生效 token。每次时基标记有 elapsed 前后包围、uptime 精度及 trace clock_snapshot，禁止用单个打点耗时充当偏移。首尾及每分钟快照；窄包围≤0.5ms，转换不确定度≤1.5ms。
3. 有界、按模式开启的记录器：关闭/点击轻量/帧诊断分开，关闭时不预分配大缓冲或安装旧绘制监听器。主线程不做逐帧 JSON、磁盘写入。合格帧试运行须覆盖稳定段120秒；所有稳定段绘制可解释为唯一关联、明确未呈现或合法无缓冲，任何未知缺失均不通过。
4. 开销：预热后5×10000记录，原始P99≤10μs；真实关键区记录累计P95≤1ms。关闭/轻量/帧诊断各三对交错60秒，保存单核CPU/PSS和全部原始差值；CPU增量中位≤2个百分点，app/目标各≤4MiB，trace服务另限128MiB；不能用工作集代PSS。每模式20对相同任务比较新增迟到中位≤1ms、P95≤5ms，无新增漏点。失败则修工具或暂停该诊断模式，不拿未通过的重型模式测正式性能。
5. 优化基线采用无trace、关闭高频观察的优化APK，保留公开滚轮/播放、原始截止、原始终态及真实目标入口回执。每组10次预热单列，实际ARM提前量逐条记录。任务串行，不在关键区查询界面/状态或做资源采样，保留停止、锁屏/旋转/断连、过期不补点与唯一派发。

## 候选与比较

候选先固定生产基线，再逐个构建和验证，绝不同时改两项：

- 绘制候选：检查浮窗已不透明的背景是否仍使用透明窗口格式；若证据支持，只改变时钟面板的窗口格式，准星透明与输入不变。若该前提不成立，记录原因，不强行实验。
- 点击候选：将可提前完成的不可变手势构造移到原有准备阶段；最后坐标/屏幕/锁定/来源检查仍在派发前，停止或失配时清理，不能提前点击或沿用旧点位。以边界与失效测试先驱动实现。

每个候选先以相同提前量4000ms、相同目标、相同源/刷新/编译状态、相同工具做探索对照：4批×25次/版本，ABBA/BAAB顺序事先固定，10次预热不入分母。保留全部失败、P50/P95/P99、最大、>50ms、提前和实际接收率；n=100的P99不作稳定尾部承诺。不能挑批次、删失败或将不同版本合并。

探索阶段若无一致收益或有安全/内存/接收回归，撤回候选。若候选有一致收益，再以独立10批×100次/版本、相同交错条件确认，不能使用探索样本填入确认分母。确认阶段尾部、最大值和接收率同时评估；有未解释的回退时不保留生产改动。不为得到漂亮的P99反复重跑。

## 实测后的协议澄清（不改变样本数或性能门槛）

- 对照 Choreographer 源码及本轮逐帧证据：动画 resync 标签与 HWUI FrameInfo 使用的原始 vsync 令牌不同。关联必须使用实际提交给 HWUI 的原始令牌及唯一窗口；不能按最大/最新令牌猜测。保留所有祖先令牌作复核，未知呈现状态不计成功显示。
- 当前窗口在本轮开始前已使用 OPAQUE，预注册绘制候选的前提不成立，跳过该项，不把已有优化再次记为收益。
- 10μs 原始打点 P99 门槛保持不变；空计时器与打点原始值分别保存。未达门槛的模式只作诊断，不用于生产收益比较。无观察器的优化 APK 仍可使用原有截止和目标入口标量回执建立独立的相对点击基线；不能因此宣称帧准入通过。
- 每轮保存原始计时器读数及复用原有校验时钟读数的 armedElapsed，不增加定时器读数、不改变截止与点击算法。实际提前量按该 ARM 校验入口报告。


## 公开驱动修订（原 discovery-01 保留为失败演练）

首批记录证明3秒选择预算不足：一次播放操作晚于新截止约379ms，却被旧任务的已完成记录误判；随后滚轮确认已自动启用，驱动再次播放造成停止。因此原批次及之后手动中止的候选批不用于收益判断，全部原始失败保留。

修订仅影响测试：准备预算固定为15秒（大于已观察选择操作6.4秒的两倍），播放前至少500ms完成控件准备，缓存公开播放节点，仍在标称提前4000ms调用公开ACTION_CLICK。必须匹配本次targetEpoch、播放之后的ARM校验时刻，并在D−750ms前完成被动状态读取。每个任务必须实际收到唯一B点DOWN/UP/onClick且生产状态COMPLETED，任何缺失、重复、停止或未闭合立即终止本批，不自动重试。终态不再用关闭记录器时的默认数字零表示。

先以新ID完成10次准入演练；通过后使用独立driver-v2目录、新协议/hash和新APK执行相同8批、每批10预热+25测量、ABBA/BAAB。旧组不被新组替换，不因延迟好坏选择重采，不改变10μs/CPU/接收/尾延迟保留规则。每批外部上限按15秒准备、4秒提前、等待/清理与裕量重新计算，最长1250秒；监督与紧急停止仍独立。

## 外部中断与独立启动

用户关闭 IDEA 后，原内嵌模拟器的 `-idle-grpc-timeout 300` 导致进程退出，`repair2-preparation-diag-01` 因心跳中断结束。恢复文件仅有4条完整任务链，第5次未闭合；保留原始文件及不完整尾部，不作为完成的性能批次。此前无观察器探索在第3次预热出现的派发前 FAILED 仍待解释，不与这次外部退出混为一谈。

沿用同一 AVD、SwiftShader、2048 MiB 和端口独立启动，仅移除 IDEA 的闲置退出选项；记录新 boot_id。重启后使用 boot2 独立目录和新 ID，先做诊断；重启前后的延迟不合并、不互作 A/B。若派发前失败原因未解释，不启动或宣称完成优化确认矩阵。

30次新增阶段诊断全部接收、无诊断失败，无法倒推旧boot的单次FAILED。新增失败专用observer，仅在异常/拒绝分支调用；off成功路径仍无高频observer，失败信息为有界标量并随原有最终状态读取，普通构建不安装该observer。两边使用相同实现并重新冻结APK。先独立做10次off准入，再决定探索；任何失败照旧停批，不能拿新成功覆盖历史未知，也不能在历史问题未解释时批准优化确认或保留。探索收益比较规则、顺序及样本量不变。
