# 计时性能优化结果

日期：2026-10-28。状态：本轮局部优化与实验已完成。严格每次 50 ms 未达标，实际点击延迟改善尚未证实。

## 最终保留与撤回

生产代码最终只修改 `ClockRefresh`：可见时的生命周期/来源状态检查统一为 100 ms，隐藏时仍为 250 ms，不再在最后五秒加速到 33 ms。独立截止调度、250 ms 输入提前准备、参考锁定和现场取时保持。减少的是临界区状态检查请求频率，约 67%，**不代表 CPU 或点击延迟下降 67%**。

TDD 先在旧实现得到预期失败，再实现固定检查周期；新增虚拟时间场景验证一秒内仅需 11 次观察（含 t=0），独立点击仍恰好在 1000 ms 派发并完成。取消、拒绝、旧回调、断开及长期校时继续由现有回归覆盖。

曾测试 `postOnAnimationDelayed(24)`，但局部画面 p95 改善没有转化为稳定的绝对误差、CPU 或点击尾部收益，已撤回。`TimedOverlay` 与本轮开始时逐字节一致；最终优化 APK 与下表“保留版本”的测量 APK 逐字节相同。未改授时算法、生产同步间隔、手势长度、提前量或失败截止上限，没有新依赖、线程、权限、忙等待、提前点击及补点。

## 实际点击

所有主性能组均未开启 Perfetto。默认 1800 ms 组的失败完整保留：

| 组 | 成功接收 / 实际尝试 | 未执行任务 | 结果 |
| --- | ---: | ---: | --- |
| 原版首次 | 0/1 | 29 | WAITING 后过期，无目标触摸 |
| 原版第二轮 | 14/15 | 15 | 第 15 次过期，无目标触摸 |
| 保留的 100 ms 轮询版 | 0/1 | 29 | WAITING 后过期，无目标触摸 |
| 后来撤回的绘制候选 | 30/30 | 0 | DOWN p95 121、最大 188 ms；onClick p95 511、最大 689 ms |

失败后停止整组，不自动重试。成功样本的延迟分布不能代表失败任务；没有为未接收填入 0 ms，也没有把未执行的任务计作通过。没有证据宣称最终版本解决了短等待过期。

在观察到短等待问题后，另行固定 4000 ms 参数做配对，目标 APK 相同，前后各 30 次全部实际接收且无提前。它不替代上面的默认组。单位为 ms，依次为 p50 / p95 / p99 / 最大值；30 个样本的最近秩 p99 等于最大值，不外推 99% 可靠性。

| 指标 | 保留版本，原绘制 | 撤回的绘制候选 |
| --- | --- | --- |
| 派发迟到 | 4 / 35 / 48 / 48 | 3 / 29 / 49 / 49 |
| 目标 DOWN 迟到 | 5 / 57 / 59 / 59 | 6 / 51 / 58 / 58 |
| 目标 onClick 迟到 | 31.5 / 86 / 127 / 127 | 34.5 / 96 / 111 / 111 |

数据相对应用计划单调截止，未包含来源时钟本身的误差；onClick 是独立目标按钮的处理回执，不是第三方业务成功。顺序小样本和不同宿主负载不能证明精确因果差值。保留版本的派发在这 30 次内均未超过 50 ms，不能据此保证未来每次或其他场景达标。

## 独立时钟对照与资源

静默对照各 120 秒、121 个有效独立京东请求；采样期间不并行编译。普通周期校时间隔均为 60000 ms，独立请求不写回应用参考。首轮预备采集流程中曾另有核心构建，是否覆盖稳定测量窗口没有精确时间证据，原轮次保留而不用于下表静默配对。

| 指标 | 保留版本，原绘制 | 撤回的绘制候选 |
| --- | --- | --- |
| 显示绝对估算偏差 p50 / p95 / p99 / 最大 | 28 / 64 / 94 / 95 ms | 25 / 59 / 101 / 128 ms |
| 显示估算偏差 >50 ms | 23/121 | 14/121 |
| 字符相对当前参考滞后 p50 / p95 / 最大 | 17 / 58 / 94 ms | 15 / 47 / 110 ms |
| 单核 CPU 区间中位 | 29.33% | 30.67% |
| 进程 PSS | 22660～24799 KiB | 23015～24378 KiB |

每组只有 4 个资源样本、3 个 CPU 区间，不能据此宣称长期功耗/泄漏结论。绝对误差是 HTTP RTT 中点估计；公网不对称延迟和请求 ID 精度没有被认证，不能当作 UTC 真值。观察的是绘制字符，并非物理屏幕发光时刻。保留版本这轮外部 RTT 区间内仍有无法确认的样本，不能将无法确认改判为通过。

绘制候选的局部滞后 p95 较低，但最大值和 CPU 并未稳定改善，点击各分位也有升有降。按本轮计划撤回，不挑选某项较好数字当作整体优化成功。

## 诊断、工具与回归

另采 5 次低频 CPU/系统轨迹，5/5 实际接收。该轨迹属于撤回的绘制候选，保留其原始标签 `opt-final-trace`，**不能当作最终保留版本的轨迹**，不与无采样组混合。目标 585 个采样记录中 584 个有 callsite；有 1 条 perf_samples_skipped 错误和 compact scheduler info，均未删除。目标主线程仍有由 RenderThread 唤醒的长等待；最长 271 ms 位于回执之后，不能加入同次点击延迟。

驱动增加有界 `LeadMillis`，默认仍为 1800 ms，拒绝越界以及与时钟/长等待混用，结果保存 requestedSamples 和 leadMillis。报告工具增加 p99、严格 >50 ms 数量/比例，以及失败快照实际回执和未执行数；历史缺少回执时保持未知。受控和未知边界测试保留 RED/GREEN。

两次采集前预检发现模拟器服务设置为空；首条仅保留工具输出转录，第二条保留原日志。恢复脚本改为先启动已被停止的普通应用，再重连模拟器无障碍服务；之后设置保持，未改变生产授权流程。候选完整功能回归另在毫秒滚轮触摸场景失败，原始结果保留，不据此猜测是绘制策略的因果回归。最终保留版另行运行完整回归。

最终保留版 60 个单元测试、完整 32 项模拟器功能、11 个分析测试、5 个报告测试通过；标准与辅助构建/Lint 通过。恢复普通 Debug 和原偏好、移除两个测试包，活动采集会话 0，IDEA 内嵌模拟器未重启。结果及指纹见 [证据索引](acceptance/2026-10-28-optimization.json) 的 checks；大文件和失败现场保留在本机忽略目录。真机与一小时持续运行本轮未重测，不把旧结果当作本轮执行。

## 授时与下一步边界

没有盲目增加请求、平均样本或长期保持最小 RTT 旧锚点。现有数据不能认证这些策略的真实精度优势；过时锚点还可能扩大振荡器漂移并推迟实际来源校正。核心长期校时与绝对锚点回归继续验证，但不是重新做了一次物理长时验证。

本轮完成的是减少可证明冗余工作的局部优化，并撤回缺乏整体收益的方案；尚未证明实际点击延迟改善，更没有达到严格每次 50 ms。后续应在真机分别采集授时误差、派发与实际接收，区分模拟器图形通信尾部；当前数据不足以给出通用的最大毫秒上限。
