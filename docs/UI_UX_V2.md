# MVP 后第一版：准星、定时单击与悬浮时钟

日期：2026-10-25。状态：已按本方案实现 0.2.0，并完成模拟器及单台真机功能验收和本机常态时钟优化；实际能力和验证边界以 FEATURES.md、VERIFICATION.md、PERFORMANCE.md 为准。绝对精度、长期功耗和更多机型待验证。

2026-10-26 后续：精简首页、浮窗时间编辑和 FPS 准星以 [UI/UX V4](UI_UX_V4.md) 为准；下方保留此前版本的设计背景。

本文取代 UI_UX_V1.md 中的下一版优先级。下一版重点为可拖动准星、限定一次的定时点击、时间选择器、仅两项配置的内置时间源页面，以及三位毫秒悬浮时钟。原 MVP 的连点和多点录制保留为独立功能，不将重复选项混入定时单击。

## 1. 用户确认的范围

| 要求 | 下一版交付定义 |
| --- | --- |
| 可拖动准星 | 准星显示在目标应用页面上，中心点即单点点击坐标；拖动和定位本身不点击目标 |
| 定时点击一次 | 选择下一次触发时刻，例如 12:59:59:750；每次启用最多派发一个点击手势，完成即结束，不提供次数输入 |
| 时间选择器 | 同一行四列滚轮选择时、分、秒、毫秒，不选择年月日或手写时间 |
| 独立时间同步设置 | 只有“内置数据源”和“同步间隔”两个可编辑配置项，没有 URL、解析格式、JSON 路径或自定义源输入 |
| 悬浮时钟 | 24 小时制 HH:mm:ss:SSS，例如 12:59:59:871；可独立显示，等待任务时与该任务使用同一参考 |

V1 草案中的多点列表重构、步骤排序及完整结果管理后移，不作为本轮扩展的必要范围。

## 2. 首页：默认进入定时单击

```text
┌──────────────────────────────────┐
│ 阿浩点击器             时间同步 >│
│                                  │
│ [定时单击]   连点   多点          │
│                                  │
│ 点击位置                         │
│ 准星中心：X 540 / Y 1200          │
│                                  │
│ 触发时间                         │
│ 12:59:59:750                     >│
│ 点击上方打开四列时间滚轮         │
│                                  │
│ 点击次数：1 次，执行后结束        │
│                                  │
│ 阿里云时间 · 最近校时成功         │
│ [显示悬浮时钟]                   │
│──────────────────────────────────│
│           [准备定时]             │
└──────────────────────────────────┘
```

图中时间与坐标仅为示例。第二步显示时钟和准星，默认恢复当前屏幕历史坐标或屏幕中心；移动准星、选择时间都不自动启用任务。

首页“准备定时”保存草稿并进入准备态，不执行手势。用户切到正确目标页面，检查准星中心与触发时间后，再点浮层顶部播放图标。返回权限设置、拖动准星、选择时间或回到应用，都不能代替这一步明确启用。

旧连点与多点拥有各自的次数、间隔规则；切回定时单击时固定为一次，不能沿用旧任务的 count，也不能把同一触发时间当作周期任务。

## 3. 准星选位

第二步打开浮窗时同时显示准星，主页面不再有“显示准星，拖动定位”，也不需要“确认位置”。

```text
目标应用页面
                │
          ──────┼──────   ← 可拖动，松手自动保存
                │

┌──────────────────────────┐
│ [▶ / ■] [四向拖动] [×] │
│ 当前时间 / 开始点击时间  │
│ 准星中心：X 540 / Y 1200 │
└──────────────────────────┘
```

- 恢复本屏幕有效历史坐标，否则位于屏幕中心；准星拖动不向下层传递点击。
- 准星中心按屏幕像素计算，浮窗随拖动更新坐标；松手保存，主页面复用现有检查显示最新位置。
- 定时等待时准星仍可拖动，到达时取最新实际中心。控制条不得覆盖目标点，启用与派发前均校验。
- 点击派发时短暂移除准星输入窗口，完成后恢复可拖动准星。关闭窗口、停止服务或屏幕变化不恢复任务。

## 4. 时间选择器

点击后直接打开四列原生滚轮，不再选择年月日，全程不弹出时间输入键盘。

```text
┌──────── 选择触发时间 ────────┐
│    时    分    秒    毫秒    │
│    11    58    58    749     │
│  [ 12 ][ 59 ][ 59 ][ 750 ]  │
│    13    00    00    751     │
│ 未到为今天，已过为明天       │
│ 仅点击一次                  │
│          [取消]    [确定]   │
└────────────────────────────┘
```

时为 00–23，分、秒为 00–59，毫秒整列为 000–999。四列横向等宽，说明可纵向滚动，横屏使用较矮的滚轮。关闭控件内部的编辑和软键盘路径。主页面和悬浮时钟统一显示 HH:mm:ss:SSS。

确认时按所选时间源参考解析下一次到达的时刻；确认后仍为绝对目标，只执行一次。最终启用时已过期则拒绝，不立即补点、不自动顺延。
时区使用设备实际时区，示例中的 Asia/Shanghai 不是硬编码。

## 5. 独立时间同步配置页

```text
┌──────────────────────────────────┐
│ < 返回              时间同步     │
│                                  │
│ 内置数据源                       │
│ [ 阿里云                    ▼ ]  │
│                                  │
│ 同步间隔                         │
│ [ 1 分钟                    ▼ ]  │
│                                  │
│ 上次成功：8 秒前                 │
│ 当前参考：阿里云                 │
│ 比设备时间快 125 毫秒            │
│                                  │
│ [立即同步]        [保存]         │
└──────────────────────────────────┘
```

严格只有两个可编辑配置项；同步状态、最近成功时间和偏差是只读信息，“立即同步”“保存”是操作按钮。移除 V1 的自填 HTTPS URL、格式、字段路径和周期同步开关。同步间隔使用选择控件，可选 1/5/15/60 分钟，默认 1 分钟；每来源至少间隔 1 分钟请求，立即同步也受此约束，不把毫秒显示理解成毫秒网络请求。

内置三个有官方说明的公网时间源，展示服务名称，地址和协议由应用维护：

| 显示名称 | 内部候选地址 | 官方依据 |
| --- | --- | --- |
| 阿里云（建议默认） | ntp.aliyun.com | [阿里云 NTP 文档](https://help.aliyun.com/zh/ecs/user-guide/alibaba-cloud-ntp-server) |
| 腾讯云 | ntp.tencent.com | [腾讯云公网 NTP](https://intl.cloud.tencent.com/zh/document/product/213/32379) |
| Cloudflare | time.cloudflare.com | [Cloudflare Time Services](https://developers.cloudflare.com/time-services/ntp/usage/) |

已从当前 Android 模拟器逐源探测：三个来源在不同轮次均曾成功，也存在超时；最终整组只有阿里云成功。页面按真实结果显示状态，不把一次探测等同于各网络均可用。默认选择不是速度或精度排名，具体记录见 VERIFICATION.md。

实现采用 NTP/SNTP 获取时间，不要求用户理解时间响应格式。其协议扩展与原 MVP 的 HTTPS 来源存在差异，见 ADR 0004；旧 HTTPS 读取器保留作回归，不暴露为自填配置。

保存新来源后发起同步，限频中显示下次同步时间；新来源不能沿用旧来源的成功标记。失败显示真实原因和最近参考状态，不静默换一个供应商。未成功校时前仍可设置任务草稿、显示带“未校时”标记的设备时间；定时单击启用前必须取得选定来源 5 分钟内的有效样本，失败时可重试或更换内置源。

同步周期与时钟绘制独立：有可见时钟、相关页面或待执行任务时按周期同步，关闭相关界面与浮层且没有任务后暂停。恢复时视样本状态同步，不申请不必要的后台常驻、精确闹钟或系统时间修改权限。

## 6. 悬浮时钟与启用控制

```text
独立悬浮时钟
┌───────────────────────────┐
│ [▶] [四向拖动]       [×] │
│ 12:59:59:871               │
│ 开始点击                   │
│ 13:00:00:750（较小字号）    │
│    阿里云 · 最近校时成功   │
└───────────────────────────┘

定时已启用
┌───────────────────────────┐
│ [■] [四向拖动]       [×] │
│ 12:59:58:920               │
│ 开始点击 12:59:59:750      │
│ 目标 12:59:59:750          │
│ 还有 00:00:00:830          │
│ 准星可拖动 · 仅点击 1 次   │
└───────────────────────────┘
```

- 固定 24 小时制 HH:mm:ss:SSS，补足两位时分秒和三位毫秒；等宽数字固定宽度，不随数值跳动。
- 时钟可以在没有点击任务时单独打开、拖动和关闭。关闭独立时钟只隐藏显示，不隐式启动或取消任务；有任务时，停止控制仍保持可见。
- 关闭控件使用右上角“×”矢量图标，触摸区域 56×56 dp，提供无障碍说明，不随内容滚动。独立时钟不再显示底部文字关闭按钮；准星/定时控制窗的“×”会取消选择或停止任务，定时浮窗移除“隐藏时钟”“启用定时”“停止定时”三个文字按钮，由顶部播放/停止切换；准星松手自动保存，无需确认。
- 顶部拖动提示使用四向箭头十字图标，图示中的“[四向拖动]”代表图标，实际界面不显示该文字。保留整块拖动区域和“拖动浮窗”的无障碍说明。
- 拖动图标左侧为播放/停止切换按钮，启用后为方块，停止后恢复三角并保留浮窗；每次点击给出开启、关闭或不能开启的短提示。通知关闭也能在浮窗内看到提示，约 2 秒自动消失，不申请通知权限。
- 主时钟下方新增 20 sp 的计划开始时刻，格式 HH:mm:ss:SSS；未配置显示“未设置”。完成和中断不自动重新开启，停止后允许修改下次开始时刻。
- 准备阶段可移动时钟和控制区避开目标点。等待阶段控制条锁定，准星仍可随时拖动，真正触发时采用最新位置。
- 启用定时后，任务、时钟和倒计时共同使用本次固定参考。后续周期同步可记录新样本，但不会让这次时钟和任务产生两套时间；界面标记“本次参考已固定”。更换来源需要先停止当前任务。
- 没有定时任务时，独立时钟使用最近有效参考；未校时必须标记，不把设备时间冒充已同步外部时间。
- 准星和数字显示区域在等待/触发阶段不能截获目标手势；停止控制保留独立触摸区域并避开目标。不能仅在代码里计数一次，却实际点中自己的准星或时钟。
- 按刷新预算更新可见数字：普通状态每 100 ms，已启用任务的最后 5 秒约 33 ms；关闭浮窗后取消显示回调。只更新数字区域，不反复创建浮层，不每毫秒重绘或联网，不忙等待。毫秒显示分辨率不代表 1 毫秒真实触发精度。

## 7. 一次性任务语义

```text
编辑草稿 → 准备/确认页面 → 启用定时 → 等待
                                      ↓ 到时
                                 派发一次手势
                                      ↓
                         已完成 / 拒绝 / 取消 / 超时

任意阶段停止、熄屏、断开服务、尺寸变化 → 结束，不恢复
```

一旦进入派发阶段，先消费本次唯一执行资格，再调用平台手势接口；失败、重复回调、超时、重连、进程重建或后续校时都不能产生第二次派发。取消或中断可能导致零次，不能为了满足“一次”而自动补发。再次执行必须由用户重新设置未来时间并明确启用。

用户选择的是计划触发时刻；平台调度、手势过程和目标接收会产生延迟。实现记录计划触发、实际派发和完成回调，验收补充独立目标接收时间，不能将倒计时归零作为精度验证。调度迟到超过 250 毫秒时过期停止；此边界不代表点击精度保证，真实偏差仍需真机测量。已过时刻启动或中断恢复一律不补点。

用户可随时一键停止，不弹确认。完成后显示“本次手势已完成，定时已结束”，不能显示“目标业务操作成功”。

## 8. TDD 与交付顺序

按以下顺序实施和验收，结果见 VERIFICATION.md：

1. 先写 RED：一次性资格、取消/超时/重复回调、过期启用、时间参考共用、选择器毫秒转换、源切换和周期取消。
2. 纯 Kotlin 中实现可测试的单次调度规则、内置源标识和时间样本模型；平台层实现时间获取、准星坐标转换与显示。
3. 以 XML / View Binding 实现默认定时页、四列时间滚轮、两个配置项的独立页面，不新增跨平台框架。
4. 实现准星定位和独立悬浮时钟，再连接准备、启用、实时取点和停止流程。
5. 独立目标验收：拖动不点击、自动保存位置、准备不点击、到时最多接收一次、准星/时钟不拦截、停止后不恢复、23:59:59:999 与跨日。
6. 逐源验证 DNS/网络可达性、样本有效性与超时；在优化构建真机测量时间偏差、PSS 和可见时钟的 CPU/刷新开销。

传统连点和多点的已有测试继续保留；不得通过隐藏或移除旧能力来规避回归。
