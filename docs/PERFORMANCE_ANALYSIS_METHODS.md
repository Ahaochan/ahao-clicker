# 性能分析方法与本轮复现

适用于本项目 V3 测量工具与 2026-10-28 的分析。对应[执行报告](PERFORMANCE_ANALYSIS_RESULTS_V3.md)和[冻结计划](PERFORMANCE_ANALYSIS_PLAN.md)。本文描述已实际执行的方法及其限制，不把尚未实现的正式矩阵写成已经支持。

## 1. 先区分四个判断

1. **D 设计准入**：计划字段、分母、预算与判断规则完整；不能证明采集工具能运行。
2. **P 实测准入**：用真实 APK 和小规模试运行检验字段、关联、开销及预算；缺项就是未通过。
3. **采集完整性**：预注册任务均有去向、原始文件无损且可重放。产品失败可以是完整负结果，采集器丢字段则是覆盖缺口。
4. **性能达标**：在完整且有效的数据上按指定阈值裁定。通过构建、回执一次、HTTP 返回成功或存在帧表均不能代替它。

本轮停在 P 未通过。7 个局部会话包括 3 个公开 UI、1 个独立参考筛查、3 个帧能力演练；没有正式 V3 样本。任何后续重试都用新 ID，失败不覆盖、也不换名替换正式名额。

## 2. 保全身份与恢复

开始前保存当前 110 个源码/工具文件的 SHA-256、Git 状态、boot、设备信息、已安装包和原始 APK/偏好/相关设置。产品源码当时已有未提交改动，不能用 HEAD 直接代表本轮起点。

测量构建使用 JDK 17、仓库 Wrapper、D 盘 Gradle 缓存；普通与测量构建分别保留，测量 APK 使用优化构建和固定 speed 编译。本轮最后安装的两个 APK 从设备再次拉取归档，不用后来重新构建的包充当当时测量包。逐轮工具修订和缺失的早期目标 mapping 均进入质量记录。

修改范围审计以实际补丁反向重建 8 个既有文件，再与本轮开始时的哈希比较，全部逐字节匹配。4 个生产文件的修改是可关闭观察钩子及保持求值顺序的局部变量；算法、截止/锁定/点按参数未改变。观察器没有安装时保持关闭，但这**不能证明开启后的开销合格**。

结束时安装备份原 APK、恢复偏好原字节、恢复无障碍列表和系统设置，核验 APK hash、服务真实绑定、零活动 trace；移除原先不存在的测试目标。保留 IDEA 内嵌模拟器，不重启、不改渲染模式、不 Root、不关闭系统安全限制。恢复工具见 `tools/profiling/restore_v3.py`。

## 3. 低干扰事件与失败可见性

观察入口放在真实方法边界。core 只暴露可空观察器；Android benchmark 观察器负责取 elapsed 纳秒、tid、固定长度入队。目标在 `dispatchTouchEvent` 和按钮监听器最前面记时，先于旧目标计数/JSON 工作；dispatch 成功、系统完成和目标 DOWN/onClick 分开记录。

二进制文件每条 64 字节、小端、8 个有符号 long：

| 槽 | 内容 |
| --- | --- |
| 0 | 从 1 开始的单调序号 |
| 1 | elapsedRealtimeNanos |
| 2 | tid |
| 3 | 高 32 位 attemptId，低 32 位事件码 |
| 4～7 | 事件对应的 a/b/c/d 原始参数 |

事件定义在 `TimingObservation.kt`。ARM 保存 T、D 和参考；REBASE_ACCEPT 保存新旧 D；目标 400/401/403 分别为 DOWN/UP/CANCEL，420 为真实 onClick，500 为本地观察点。坐标按原始 float bits 保存。二进制零槽位只是原始格式占位，分析结果对缺失 DOWN/呈现/参考使用 null 与 reason，不解释成零延迟。

两个固定缓冲各最多 31744 条，不覆盖未落盘记录；后台写入，任务关键区暂停普通文件写出；序号、溢出、错误、刷盘状态随结果保留。头部文本队列有界；不记录任意 HTTP body。容量上界不是 PSS 开销证明，实际的三对基线/观察配对尚未通过。

宿主每 500 ms 检查独立每秒心跳；缺失超过 5 秒或外层超时则停止本轮自己的任务进程，不清除无关 trace。每条心跳保留设备时间及宿主接收时间；它不是完整双向时钟包围。设备 PSS 每 30 秒采样，宿主 CPU 原始计数每秒保存；驱动与目标同进程，不能编造第三个独立驱动 PSS，也不能把宿主工作集当 Android PSS。

## 4. 任务与时间链路还原

一个公开任务从定位/打开选择器等准备动作开始进入尝试台账；本轮两条滚轮失败均发生在播放前，属于采集器失败，不能记为产品漏点。

公开流程不调用旧 `prepareTimed` 来直接注入任务。第三次试运行保留选择器原有毫秒值，设置时分秒并核对值，通过确定、播放启动；这只是受限可行性演练，**任意毫秒滚轮和整套故障驱动仍未完成**。

按 ARM 后首次有效引擎终态结束任务；后续清理 STOP 另记。最终 D 取有效 REBASE_ACCEPT 后的截止；没有重算才用初始 ARM D。DOWN/UP/onClick 按同 attempt、串行窗口、时序与目标 B 联合归属。重复、取消、未闭合和错点分开，不能只看计数清零。

对入口 m，用 `L(m)=m−D`，保留负值。分别拆为截止回调排队、回调内工作、dispatch→DOWN、DOWN→UP、UP→onClick。系统完成回调与目标接收可能交错，不强制串接。字段缺失保留 null，不能将没有接收的任务从失败分母移除。

所有本地链路使用同 boot 的 elapsed 纳秒；原始 MotionEvent uptime 单列。当前局部演练没有完成 V3 所需的全套 clock_snapshot、双向宿主包围及每分钟转换验证，不能把当前诊断当成已通过所有跨时基门槛。

## 5. 独立参考的区间而非单一数字

独立工作线程请求同一个京东 OPTIONS 接口，不共享应用连接、锚点或 parser。头名大小写不敏感；原始多值头折叠相同值，冲突拒绝；第三段必须严格为 13 位 Unix 毫秒且落在规定范围。非 2xx、缺头/坏格式/冲突、非法 Age 或 Age>0 均无效。Age 缺失不等于证明没有缓存。

定义完整调用开始 s、响应头接收 r、头中时间 S，以“时间戳在请求期间生成、短窗口内来源与 elapsed 等速”为**未认证模型假设**：

```text
点估计 R(m) = S + m − (s+r)/2
区间 I(m) = [S + m − r − 1ms, S + m − s + 1ms]
```

connect 之后的窄边界只作辅助，不能代替完整边界；数据不会仅因连接慢就被换成较小 RTT。外推年龄超过 5 秒无效。前/后分别保留估计：不相交即 conflict；相交取两区间的保守包络，不取交集、平均或最小 RTT。

允许点击 `[0,50] ms`，显示 `[−50,50] ms`。整个误差区间都在内才是 conditional_within，完全在外才是 conditional_outside，部分交叠为 inconclusive；参考缺失或模型条件不足为 not_evaluable。点估计越线与确定越线分别报告。

本轮 20 对请求没有附带实际点击，故是**能力预检而非正式任务级 P**。完整 RTT 最短约 99 ms，配对包络最窄约 107 ms，已显示当前方法没有 50 ms 可判定能力。不能把区间宽当成产品延迟，也不能用旧的窄 RTT 历史样本填补这个缺口。

应用自然请求的 `connectBegin/End` 与现有 sent/received 也分别保存。连接阶段 wall time 包括线程未运行的时间，不自动等于网络耗时；全边界中点与窄边界中点之差，也不自动等于真实授时误差。要解释它，需要实际发送语义及同窗口调度/网络证据；本轮不修生产实现。

## 6. 绘制、帧身份和系统呈现

字符 epoch 在原有 onDraw 中读取，不主动追加绘制。drawId 二进制记录与同作用域 Trace counter 对齐，沿 slice 父链找到 Choreographer frame token（包括 resync）；再按**精确 token**关联唯一应用 surface frame，按 display token 关联唯一 SurfaceFlinger display frame。系统报告的实际显示帧结束才作呈现时刻。

禁止最近时间猜配、将应用 ActualTimeline 结束冒充呈现、从其他窗口补缺。存在多个 surface/display 候选、未完成或丢弃帧时保留 reason。观察点只能取此前最后已知呈现帧；若中间出现未能关联的绘制，标无法确认，不能继续假定旧帧仍在屏幕。

同一 drawId 的二进制入口与 trace counter 时间差包含钩子执行及被调度出去的时间，**不纯粹是时钟偏移**。本轮发现部分差值超过 1 ms，同时还存在未定位到具体窗口的 FrameTimeline 解析错误，因此帧关联可用于局部诊断，不能通过严格 P。

两轮有效帧试运行各有 121 个本地点，没有独立外部探针。分析只给画面年龄与相对最近已观察应用参考的诊断值；不输出它们的来源绝对误差。这里的呈现是 guest 系统报告值，不认证物理屏幕的光学延迟。

DISCARD + 流式写出的配置警告按原样保留。RING_BUFFER 对照只去掉该配置警告，未消除所有解析错误/关联歧义；它不是通过单个开关就证明新配置整体更快。两轮也未完成随机配对和开销标定，不作因果优劣比较。

## 7. 火焰图、调度和异常归因

历史 15 份原始 trace 全部复制到新目录重新运行 Trace Processor 和已有分析器，保留新 SQL/export、全部 stats、运行火焰图及最慢点击时间线；原文件不覆盖。每份新 summary 的 trace SHA-256 与对应原文件核对。

CPU 火焰图只描述 on-CPU 栈占比。S/blocked、R/runnable 与 Running 按同一个异常窗口分别裁切，嵌套 slices 不重复相加；阻塞窗口须结合唤醒者和该次事件栈。一次长 postAndWait 若发生在回执之后，就不能用它解释此前点击迟到。

历史 RenderThread 唤醒链可以定位图形通信路径，但不填补本轮 W 事件栈的缺项。guest Running、图形热点或宿主整体 CPU 高只能提供相关证据；未取得宿主模拟器进程 CPU/GPU、真机同协议对照时，不能定论为设备性能上限或“优化到极致”。

## 8. 统计、长期趋势与图表

分位数固定最近秩 `x[ceil(p*n)]`，P50 不用两个中间值平均。给 n、最小/最大、提前、>50 ms、原始失败和未执行。历史按 15 个 APK hash、提前量、采集模式和批次隔离；47 份历史结果的 481 个点击记录不合成一个总体 P99。小样本 P99 常等于最大值，不声称稳定尾部估计。

长期曲线保留实际观察时刻、每次同步与参考变更。不得把 30 秒外部采样插值成每秒独立真值，也不跨同步跳变拟合一条“振荡器漂移”直线。历史一小时的 121 个估计误差只说明当时观察结果；没有本轮 F/G/P-long，不作新的长时达标结论。

图表的数据 ID 和原始字段随图保留。当前可绘制独立参考宽度、局部帧年龄/呈现、分批历史迟到及 PSS；W 事件栈、小时级新数据或独立外部画面误差缺失时明确空缺，不画想象中的曲线。PSS 的少量升高也不自动等于泄漏。

## 10. 停止和下一次工作的边界

本轮帧能力类别已达到计划限定的三轮演练，仍有质量与时基缺口；来源预检也没有可判定的 50 ms 区间。因此正式 27 组保持未启动。没有通过开销门槛的打点数据不能用来声称精确产品分布。

下一步应先明确并修复已定位的测量缺口：任意毫秒公开驱动、可验证的帧/时钟关联和解析质量、严格过滤的 W 控制样例、配对开销、真实参考发送/生成边界。更改 DISCARD 正式策略须保留协议版本差异并重新核对受影响门槛。正式准入全过以后才值得花数小时跑长等待；不要仅为了较好 P99 再跑一次。


## 2026-10-28 测量修复后的规则

1. 原始 FrameTimeline 包逐字段审计，并与固定版本 Trace Processor 的错误数对账。结构缺失、非法时刻、缺少 cookie 与呈现类型枚举未知分别报告；保留原始 trace，不删错误计数，不用 experimental 类型覆盖主类型的未知值。
2. 关联先取得创建前设置的唯一时钟窗口标题，再使用 HWUI FrameInfo 实际提交的原始 vsync token 与显示 token。Choreographer 的动画重同步标签不能作为“最新帧”直接替换缓冲 token；任何窗口/令牌歧义、未知呈现类型均保留，不用最近时刻猜测。
3. counter 与较早业务记录的差值包含线程暂停和调用成本，名称是打点调用延迟，不是时钟漂移。Trace 主时基为 BOOTTIME 时，以 clock_snapshot 验证与 elapsedRealtimeNanos 的同域关系；每个校验 marker 由前后读数包围。另保留 uptime 毫秒量化和快照读数非原子的不确定度。
4. 打点开销须报告空计时器与完整记录路径的原始分布，不能将两个 P99 相减作为“真实 P99”，也不能因模拟器较慢而事后放宽预注册门槛。原始记录器未达门槛时，保留诊断数据，生产优化比较关闭观察器与 trace。
5. 关闭观察器的基线不使用旧逐帧字符串监听器。计划截止来自生产任务状态，ARM 校验时刻复用原有时钟读数，目标入口记录实际 DOWN/UP/onClick。它验证相对本地截止的接收延迟，不证明数据源绝对准确。
6. 单变量实验事前固定顺序、预热数量、样本数、接收分母与保留规则。P95、P99、最大值、提前点、漏点及未执行项一并保留；候选不满足规则就撤回，不反复重跑到出现漂亮结果。

本轮固定协议见 [测量修复与单变量优化计划](MEASUREMENT_REPAIR_PLAN.md)。精确解析器依据 [Perfetto add693d8](https://github.com/google/perfetto/blob/add693d8b338ba9599dbcbc3e300b1ab8c000897/src/trace_processor/importers/proto/frame_timeline_event_parser.cc)，时基依据 [Perfetto clock sync](https://perfetto.dev/docs/concepts/clock-sync)，令牌传递依据 [AOSP Choreographer](https://android.googlesource.com/platform/frameworks/base/+/HEAD/core/java/android/view/Choreographer.java)。来源快照与逐帧验证证据保存在本轮本地归档，不把系统源码的其他版本直接当作设备行为证明。

### 失败诊断与外部中断

关闭观察器的历史 FAILED 没有阶段原因时，不能通过随后成功或一个受控反例倒推出历史原因。补充失败专用记录：32为准备异常，46为坐标解析/驱动调用异常，文本使用既有有界通道；107的原因1为缺少准备结果、2为任务状态失效、3为缺参考、4为超过迟到边界、5为忙或锁屏、6为屏幕变化、7为越界。不增加重试、不取消保护；观察器写入异常也不能改变任务失败结果。

模拟器外部退出与产品任务失败分开记账。重启产生新boot_id，所有延迟按启动批次隔离。中断文件不修补成完整文件；若可读出连续完整前缀，只另存不完整诊断说明并保留全部原始尾部。独立启动移除IDEA闲置退出选项不视为生产优化，前后数据不能互作对照。

### 主机心跳的时钟分辨率

本机实际Python3.12.14的`time.get_clock_info('monotonic')`返回`GetTickCount64()`，分辨率15.625ms。字段名中的Ns只表示数值单位，不能据此假定纳秒精度。前三个完整探索批的设备/主机时长分别约843/842.985、843.000761/843、844.000282/844秒；端点差包含该量化、管道传输及读取排队，不能解释为振荡器漂移，也不能证明外部绝对50ms。

该主机时钟仅用于现有0.5秒监督、5秒心跳超时及主机资源日志；本轮点击截止、实际入口时间和帧关联使用Android/Trace的设备时基，没有用主机端点拟合。采集中不更换时钟或工具。后续新增主机高精度关联必须显式记录实际后端、分辨率和包围误差，旧主机Ns字段不能直接加入1.5ms设备时基预算。原始核对与运行时信息另存`boot2/heartbeat-duration-sanity-first3.json`。

### 未知呈现类型不能等同于丢帧

[Perfetto定义](https://perfetto.dev/docs/data-sources/frametimeline)中，应用Actual Timeline结束是GPU完成/提交的边界，不是屏幕呈现；应沿令牌关联到SurfaceFlinger的DisplayFrame。Present Type另描述相对预期的早/准/晚分类。

[AOSP固定快照43a68c3](https://android.googlesource.com/platform/frameworks/native/+/43a68c3fd6da28753a612965b4072ef93f9f888e/services/surfaceflinger/FrameTimeline/FrameTimeline.cpp)将UnknownPresent分类转换成PRESENT_UNSPECIFIED，也会在SurfaceFrame的PresentState为Unknown时写同一值。仅凭原始present_type=0不能区分这两条来源：不能全部当丢帧，也不能全部认定已经显示。该快照用于说明编码歧义，不冒充设备的精确源码版本。

因此本轮666条保留为呈现证据不足的未知，既不计作显示成功，也不填成确定丢帧。此复核不改变既定准入门槛、不使用experimental类型覆盖主类型；若要解除这类未知，需要独立的已呈现证据或可验证的生产者状态，不能仅删除处理器错误数。

### 完整探索的数据质量审计
