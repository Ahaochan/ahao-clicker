# ADR 0012：现场取时绘制与 50 ms 验收边界

- 日期：2026-10-27。
- 状态：已实现绘制优化；严格 50 ms 性能验收未通过，不能据此承诺硬上限。
- 替代 ADR 0005 中由 100/33 ms 服务轮询更新悬浮数字的决定；ADR 0011 的参考选择、有效任务最后五秒锁定、结束后使用最新参考继续有效。

## 决定

ClockFace 在 onDraw 内按选定参考的绝对锚点和 elapsedRealtime 计算数字，不再显示服务轮询提前算好的 epoch。服务只负责状态、生命周期和长任务校时，不以屏幕绘制安排手势。

可见且附着的时钟通过框架安排下一次重绘，最小请求间隔 16 ms；实际绘制由系统帧时序决定，在本轮 60 Hz 模拟器通常约 30 帧/秒，不能将此请求间隔宣传为每 16 ms 必然绘制。隐藏/移除后不再续约重绘，不新建线程、忙等待或格式化器。复用字符数组与 Paint，读屏描述仍只每秒变更。未使用 VSYNC 时间戳代替 elapsedRealtime，没有人为把数字提前来掩盖滞后。

浮窗面板使用不透明窗口和同色纯色背景，去掉重复背景填充，准星窗口仍透明。减少无意义混合，修正高频整个窗口刷新带来的负载；布局尺寸与交互语义不受此决定影响。

重绘只保留一个复用 Runnable。每次绘制先移除此前请求，再续约一次；移除 View 时主动取消。父布局或按钮水波纹提前触发绘制也不会累积多条重绘链。

## 输入窗口切换

扩展实际接收时出现“派发晚 5 ms、系统报告完成、目标触摸 0”的证据，不能将系统完成作为真实点击成功。为窗口切换预留更多余量：提前 250 ms 收起准星，至少准备 150 ms，再在绝对截止派发；这不是提前点击，也不是补点。最后约 250 ms 准星不再拖动，停止仍可取消。输入窗口切换并无公共硬实时确认 API，此余量仍需以实际接收复测，不是永不丢失的证明。

## 测量

基于 [View 绘制](https://developer.android.com/reference/android/view/View) 与 [Choreographer](https://developer.android.com/reference/android/view/Choreographer) 的帧调度，不把定时回调当作绘制完成。benchmark 的 OnDrawListener 在子 View 绘制之前运行，观察器因此在遍历后读取实际字符；不主动触发绘制来挑选有利采样时刻。独立请求不写回应用参考。

50 ms 作为严格样本门槛：全部样本保留，任何有效样本估算绝对偏差 > 50 ms 就失败。另报告 `max(0, |估算偏差|-RTT/2)` 和 `|估算偏差|+RTT/2` 的解释区间；区间跨越 50 ms 只能标为无法确认。这以请求 ID 的确代表请求期间的服务端时间为假设，不是公开授时 SLA 或绝对 UTC 认证。

结果与代价见 [实测记录](../CLOCK_50MS_RESULTS.md)。当前 Android 主线程、软件图形管线和公网时间接口都没有提供任意情况下每次 <= 50 ms 的保证；观测中仍有越线，性能门槛保持失败。
