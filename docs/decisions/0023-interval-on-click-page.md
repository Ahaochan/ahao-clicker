# ADR 0023：悬浮时间同步间隔放在自动点击页

- 日期：2026-11-03。
- 状态：已实施，本地检查和模拟器回归通过；真机未复测。
- 用户要求将该配置放到“自动点击”页，更新ADR 0006的页签职责；来源选择、校时比较和卡片排序仍位于“时间同步”页。

## 决定

1. 将间隔字段、来源最低间隔说明及“保存并同步”移到定时/多点浮窗入口下方，不增加第三步编号；时间页只呈现来源卡片及括号差值说明。
2. 间隔面板负责输入、校验提示、键盘和可编辑状态，来源面板负责选择、比较与排序；两者共用同一TimeSettingsController。Activity保留草稿与选中页签，切页和重建不把未确认间隔写入偏好。
3. 保存后仍对全部来源同步一次，保持选中来源浮窗的周期需求。间隔保存由全量同步回调统一应用配置，不先以“没有比较页观察者”为由暂停在途请求；显式单次需求由当前Activity在自动点击页持有，进入时间页后先合并到比较页需求再释放，后台也释放。普通首页可见不会发起请求，也不因该需求创建周期同步。
4. 页面初始化、显式保存和卡片点击继续是不同入口：进入时间页全量一次，点击卡片只请求选中来源，手动保存全量一次。排队/在途请求继续合并，HTTP/NTP最短间隔、任务保护、取消旧响应和本地无需联网规则保持。

## 验证

- 旧版先复现自动点击页没有配置、间隔保存不必要地执行观察者刷新；实现后覆盖配置位置、错误输入、保存及未保存草稿跨页/重建、活动任务保护。
- 用假来源和真实TLS计数确认手动需求只有一次、切页时复用、关闭时取消且浮窗需求保留；普通首页不订阅周期网络。
- 回归来源点击、实时拖动、大字体横竖屏；运行标准检查并区分模拟器与真机结果。
- 结果：131项单测、Lint零错误零警告、Debug/Release及API37模拟器7组定向回归通过，原始失败与通过证据索引见[验证记录](../VERIFICATION.md)。
