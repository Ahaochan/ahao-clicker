# ADR 0003：时间同步、定时连点和实际点击录制

- 日期：2026-10-24
- 状态：20 个单元测试、模拟器功能验收和完整构建通过；真机性能及兼容验收待完成

用户要求按 TDD 实现三个功能：可配置外部时间源及周期同步、时间段内限次连点、多点录制与逐步间隔；并明确录制时也必须实际点击。

保持 Android 原生和两模块结构。新增纯 Kotlin 时间参考、串行点击状态机、限长录制模型与步骤文本编解码。Android 仅提供 HTTPS 数据源、SharedPreferences、Handler 调度、无障碍手势及两类浮层。除 JVM 测试使用的 JSON 实现外，不添加生产依赖。

时间源限定 HTTPS，支持 HTTP Date 和 JSON 秒/毫秒。请求串行且响应有上限；同步失败保留最后样本，切换来源清空样本。点击任务冻结启动时的时间参考，避免网络同步引起调度跳变。

录制采用主动采集与无障碍重放，不承诺获取其他应用原始触摸。先隐藏采集层再实际点击，成功后恢复，仅保存完成点。点位间隔为上一个手势完成至本次实际派发的等待，可在首页修改。总次数语义统一为手势次数。

模拟器验收曾复现窗口拆装时的漏点，并发现原图形渲染导致主线程绘制阻塞。当前保留采集窗口，通过透明度与 NOT_TOUCHABLE 临时让出输入，等待窗口更新后派发，再缓冲恢复；暂停期间忽略旧输入，停止后通过代次标识使回调失效。浮动控件固定宽度与状态行数，避免进度文字改变停止按钮位置。录制明确提示等待恢复，不承诺快速触摸的无损录制；回放不增加录制缓冲。

验收使用可选辅助模块和系统 Instrumentation，无额外生产依赖。HTTPS 信任只在测试进程加入本轮生成的本机证书，生产证书校验保持不变；目标接收事件与系统派发计数分别核实。详见验证记录和可复现脚本。

TDD 按时间参考与调度、步骤输入、未完成点持久化、响应解析、来源重置分别执行 RED，再实现 GREEN。当前核心正式 Gradle 测试结果与 Android 验证缺口见 [VERIFICATION](../VERIFICATION.md)。

完整行为见 [FEATURES](../FEATURES.md)。不承诺精确闹钟、进程终止后仍运行或未经真机测量的低内存数值。
