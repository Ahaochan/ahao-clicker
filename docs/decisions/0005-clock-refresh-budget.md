# ADR 0005：悬浮时钟刷新预算

- 日期：2026-10-25。
- 状态：已实现并通过本机功能与资源复验；长期功耗、多设备及更长运行趋势仍待验证。

## 背景

真机独立时钟持续约 30 Hz 刷新时，重测约占单核 CPU 17.7%，渲染线程与主线程均有明显开销。数字显示需要便于观察触发时刻，同时应减少远离触发时刻和独立看时钟的持续成本。

## 决定

普通时钟、准备状态、任务完成状态及距离触发超过 5 秒时，以 100 ms 间隔更新数字。只有已启用任务的最后 5 秒提高到 33 ms。隐藏数字后保留 250 ms 的取消/锁屏/显示尺寸检查，屏幕中断广播仍会立即停止；关闭浮层取消所有显示回调。

点击调度与显示策略分离，单调时钟截止回调、一次资格、过期边界和冻结的时间参考保持不变。缓存固定目标格式化结果；首页相同文本不重复设置。策略位于 core，以可见性及剩余时长为输入，不依赖 Android 类型。

## 代价和证据

常态数字最多每 100 ms 刷新，但始终格式化实际参考时刻，不伪造额外精度。临近触发仍有较高刷新成本；主线程阻塞仍可能推迟平台调用。硬实时、逐毫秒绘制和整机功耗不在本次承诺内。

同机优化包常态时钟 CPU 从 17.705% 到 6.421%，降低约 63.73%，PSS 中位数未增加。35 个单测、12 组真机回归与优化包 20 次实际多点接收验证通过；完整方法和限制见 [PERFORMANCE.md](../PERFORMANCE.md)。

悬浮时钟的 100/33 ms 数字刷新部分由 [ADR 0012](0012-clock-paint-time.md) 替代，原有状态检查与来源比较卡片预算保留。
