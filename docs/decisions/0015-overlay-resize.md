# ADR 0015：半透明控制浮窗与底角缩放

- 日期：2026-10-30。
- 范围：定时和多点控制浮窗，不缩放准星或时间/延迟设置对话框。
- 更新：[ADR 0016](0016-responsive-overlay.md)取代最小宽度/按钮尺寸规则；[ADR 0017](0017-overlay-size-memory.md)取代下文的会话尺寸规则，两种浮窗均持久化记忆宽高。

控制浮窗背景采用70%不透明度（#B318231E），文字和图标保持不透明。窗口使用TRANSLUCENT格式，不通过父View.alpha或额外离屏图层改变整个内容的透明度。

左右下角均有48dp触摸区域和对称角标，按住拖动改变宽高；左下角以右边为横向锚点，右下角以左边为锚点，顶边保持固定。只调整控制窗口，不改变屏幕准星尺寸、坐标或任务点位。尺寸仅在当前窗口会话保留，新开窗口仍用默认大小。

两种浮窗复用OverlayPanel和缩放手柄。最小宽度由可见控制数量与既有56dp触摸尺寸决定，最小高度保留页头、内容区和底角手柄；系统栏和刘海区域排除在缩放边界之外，极小屏幕优先限制在可用区域。页头及底角不滚动，内容区可滚动，初始最大高度为屏幕的3/4，用户设置的明确高度由布局尊重。播放/等待执行时与既有移动规则一致，冻结缩放，停止、关闭始终可用；停止后恢复尺寸调整，多点沿用500ms输入排空。

仅在拖动且尺寸发生变化时更新WindowManager，没有新增常驻线程、轮询、生产依赖、位图或动画。几何规则留在app，core的点击和校时算法不变。透明混合和用户扩大窗口的实际性能影响本轮不作保证，不能沿用旧版不透明窗口的性能结论。

验证采用纯JVM几何边界测试，以及模拟器的两种浮窗双角放大/缩小、最小尺寸控件可见、系统栏边界、准星独立、未触发点击、执行中冻结和停止可用。通过构建和功能检查不等于真机性能或毫秒精度验证。
