# ADR 0004：内置时间源与一次性定时任务

- 日期：2026-10-25。
- 状态：0.2.0 已实施；本轮 35 个单测、构建、12 组真机回归与优化包实际点击检查通过，既有模拟器记录保留。常态时钟刷新优化见 ADR 0005；绝对精度和长期占用仍待验证。

## 背景

用户要求下一版增加可拖动准星、只能执行一次的定时点击、完整时间选择器，以及 24 小时制 HH:mm:ss:SSS 悬浮时钟。时间同步使用独立页面，且只有内置来源和同步间隔两个配置项。

## 设计决定与建议

- 定时单击为独立模式，固定一次，不复用可配置次数的连点界面。消费唯一执行资格后才能派发，失败不重试，中断不恢复。
- 准星中心是坐标来源，拖动不注入手势。2026-10-26 起等待时仍可拖动，触发时读取最新点位，取代旧的等待锁定决定，见 [ADR 0008](0008-live-crosshair.md)。控制条和时钟不得覆盖目标点。
- 2026-10-26 更新：定时单击取消日期选择，改为同一行四列原生时、分、秒、毫秒滚轮（毫秒 000–999）；确认时以所选来源参考解析下一次发生的本地时间。未到为今天，已过为明天；保存绝对目标，不形成每日重复任务。传统连点起止日期保留。
- 时间设置界面不再暴露 URL、JSON 路径或格式等协议参数；建议内置阿里云、腾讯云和 Cloudflare 的公开 NTP 地址，具体地址与官方引用见 UI_UX_V2.md。
- 采用轻量 NTP/SNTP 实现内置源，扩展 ADR 0003 的 MVP HTTPS-only 边界；已添加报文校验、2 秒超时、每来源 1 分钟限频、取消及来源重置验证。保留纯 Kotlin 核心与 Android 网络边界，不引入生产依赖或 NTP 守护进程，不修改系统时间，不关闭 TLS 校验。SNTP 不具备 NTS 身份认证；协议依据 [RFC 5905](https://www.rfc-editor.org/rfc/rfc5905.html)。
- 模拟器各轮中三个来源均曾成功，也出现超时；最终整组只有阿里云成功。逐源结果写入本版验证记录，失败时不冒充同步成功，不擅自换源。
- 悬浮时钟在任务等待期间使用该任务固定的同一参考，避免后续校时让显示时刻与触发依据不一致。空闲时可使用最新有效样本。
- 绘制刷新与网络同步分离，不忙等待；真实时间偏差、PSS 与 CPU 通过真机优化构建测量，不能把三位毫秒显示当成精度承诺。

## 与现状的关系

旧 MVP 的 HTTPS 解析保留作回归，不再暴露自填配置；限次连点和实际点击录制保留独立模式。旧验收记录不改写，新版检查另记。定时单击要求 5 分钟内有效样本，250 毫秒迟到边界采用过期停止；均不表示真实点击误差保证。

2026-10-27 后续：长等待校时与提前输入准备由 [ADR 0010](0010-deadline-and-clock-discipline.md) 更新，取代整段等待冻结参考和到点后固定等待 50 ms 的规则。
