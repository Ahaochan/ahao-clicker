# ADR 0018：本地时间源、来源排序与10ms滚轮

- 日期：2026-11-01。
- 状态：实现完成；设备验收范围见VERIFICATION及本轮证据索引。
- 更新ADR 0006的来源目录与固定排列、ADR 0009的毫秒滚轮粒度；不改变一次性点击、输入准备、取消及停止保护。
- 后续：2026-11-02页面/浮窗同步需求规则由[ADR 0019](0019-time-sync-demand.md)更新，本地时间仍不发网络请求。
- 后续：2026-11-03来源卡片改为紧凑单列，取代下方两列呈现；排序与持久化规则保持，见[ADR 0021](0021-single-column-source-cards.md)。
- 后续：来源卡片点击会同步一次选中源，拖动中实时预览并有让位动画，松手才保存，见[ADR 0022](0022-source-card-interaction.md)。

## 决定

1. `BuiltinTimeSource.LOCAL`追加在现有枚举尾部，保留旧枚举顺序及按名称保存的来源配置。默认参考仍为原来源；未保存顺序时保持京东、淘宝、阿里云、腾讯云、Cloudflare顺序，本地时间排最后。
2. 以`TimeProvider`隔离本地和网络实现。`LocalTimeProvider`读取系统墙上时间及单调时间，不使用DNS、HTTP、UDP、定时执行器或外部同步间隔。稳定时复用参考，超过1ms偏差重新取系统时间，避免每次页面轮询都重排截止任务。`TimeReference.synced`在该显式来源下表示可供任务使用，不代表完成外部校时；UI明确标注手机系统时间，差值以同一帧本机读数计算为0。
3. 任务仍使用现有单调截止、校时更新和最后5秒锁定；系统时间/时区变化等现有广播继续停止任务。本地时间源精度由手机系统时钟决定，不声称具备网络授时精度或硬实时保证。选择本地源不会关闭比较页其他卡片的正常同步；本地源自身不产生网络请求，退出比较页仍按原观察者规则暂停其他来源。
4. 两列卡片使用系统长按拖放，携带仅本页面可验证的来源身份及会话；放到另一张卡片时按行顺序插入，其他卡片相对次序保留。拖到外面、取消、切页及旧页面事件不保存；拖动结束恢复透明度。不改变选择、未保存的同步间隔及点击任务。支持读屏的向前/向后移动操作。
5. 顺序按来源名称保存为独立偏好。恢复时去重、忽略未知项、补齐缺失来源；不依赖界面下标识别时间源。排序只在有效变化后保存，不增加定时刷新、线程或依赖。
6. 毫秒滚轮使用0～99索引，对应000、010…990。旧记忆344ms打开时向下映射到340ms，仅确认才保存新值，取消不改原草稿/记忆；新开浮窗仍取当前小时并沿用记忆的分、秒、毫秒。多点延迟数字输入仍是原毫秒粒度。
7. 原生NumberPicker在最大索引99时会按两位数字过滤输入文字；三位格式可能使000中间值空白。毫秒列改用固定100项`displayedValues`，每次打开对话框有限分配，不逐帧创建标签。真实滚轮滑动、000/990显示、确认/取消和横竖屏大字号均须设备验收。

## 顺带整理与范围

架构清单A2对应的来源选择、间隔校验、活动任务限制、保存和应用集中到无View依赖的`TimeSettingsController`，使用假回调做单测；页面负责输入和展示。存储中的来源解析与区间验证继续复用现有类型。来源顺序属于展示偏好，允许任务运行时整理，不改变运行参考。

A4已评估：本轮用独立本地适配避免走网络管理器，网络管理器明确拒绝LOCAL配置。既有URL、字段和协议搬迁留待真实接口变更，避免同时改变已验收的网络路径。A1、A3继续按需跟进。
