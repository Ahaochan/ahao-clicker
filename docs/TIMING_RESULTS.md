# 定时准时性与长期时间稳定性记录

日期：2026-10-27。验收范围：用户确认“本轮仅用模拟器验证”；本轮范围内的优化与验收已完成，真机另期进行。当前环境：API 37、x86_64、1080×2400、SwiftShader 模拟器。没有连接真机；本记录不代表手机或绝对 UTC 精度。

## 方法

测量包继承 R8/资源压缩 Release，临时使用本机调试证书签名，确认无 debuggable 标记。只在 benchmark 构建提供同签名权限保护的控制 Provider；正式 Debug/Release 不包含它。驱动附加在独立接收进程，应用进程不附加 Instrumentation 或调试器。目标记录真实 DOWN 和 onClick；应用记录计划单调截止与实际派发时间，不把派发成功等同于接收成功。

每组 30 个独立单次任务，单次等待 1800 ms，目标同一个 B 按钮；没有提前派发或自动重试。本轮沿用用户配置的京东 OPTIONS 来源，间隔 60000 ms；X-API-Request-Id 时间含义为实测推断，不是有精度承诺的授时协议。指标相对**应用内计划单调截止**，不含服务器时钟本身或单向网络不对称造成的授时误差。

单位：毫秒。p50 为中位数，p95 使用排序后向上取整位置；每组 30/30 实际接收，提前 0 次。

## 长时间等待

一次 1805000 ms（超过半小时）的明确启用任务已完成，最终实际收到一次 B，未提前或额外点击。派发晚 2 ms、目标收到 DOWN 晚 10 ms、onClick 晚 23 ms。

- 61 次状态观察横跨 1800333 ms，覆盖 31 个成功校时样本；全部观察均有效，样本最大年龄 59861 ms。采样时任务参考与最新京东参考之差均为 0 ms；这是同源跟踪结果，不是独立 UTC 误差测量。
- 与最初截止相比，后续校时修正范围为 -24～+5 ms，任务未一直冻结旧样本。最后 5 秒锁定的独立功能测试已通过；单次网络 RTT 的变化仍可能影响授时估计。
- 59 次进程外资源采样确认同一 PID/启动身份。单核 CPU 区间中位数 3.69%、p95 4.27%，最大区间 7.62%；每段约 30 秒，不能当作瞬时峰值上限。
- TOTAL PSS 为 22411～26548 KiB（约 21.9～25.9 MiB），末尾 26312 KiB（约 25.7 MiB）；预热后也有回落，未据该窗口宣称永久无泄漏。CPU 由 /proc/PID/stat ticks、CLK_TCK=100 与 /proc/uptime 的实际时间差计算，不使用瞬时 0% 结论。

虚拟时间另覆盖 30 天不规则读时与新的校时锚点，验证计算不依赖刷新次数；它不能替代真实设备/长时测量。本轮按用户确认仅在模拟器验收；真机未验证，另期安排。

## 第二组短时复测

半小时测试后，同一优化 APK 再执行 30 次，全部实际接收。DOWN 为 4 / 10 / 11 ms，onClick 为 31.5 / 46 / 54 ms（p50 / p95 / 最大）。两组共 60 次：派发 2 / 6 / 13 ms，DOWN 4 / 11 / 25 ms，onClick 30.5 / 45 / 54 ms，提前 0 次。

新增 UP 记录显示：30 次输入事件的 UP-DOWN 均为 1 ms；实际收到 UP 到 onClick 的间隔 p50 22.5 ms、最大 50 ms，剩余延迟发生在平台/目标处理链路，不能靠点按持续时间等同替代。

复测中每约 2.7 秒新建并关闭一次浮窗，两个 CPU 采样区间为 31.6～33.0% 单核，明显高于长等待；不能用等待时的 3.69% 代表频繁窗口交互或点击负载。该组 PSS 三次采样为 22172～27029 KiB；不同负载不作直接增量比较。

## 回归与复现

- 55 个单测失败/错误为 0；28 项 API 37 功能场景全部通过，含长等待重新校时、最后五秒锁定、异常大跳变终止、缺失有效样本不点击、准备中取消、断开与实际单次接收。见 [功能验收](acceptance/2026-10-27-timing-functional.json)。
- 标准 Lint、Debug 与 R8 Release 构建通过；benchmark Lint 无错误/警告，独立目标的旧 API 调用已修正，不增加应用生产依赖。
- 首轮新长等待测试未等输入窗口就绪，第二次播放触摸落到目标页空白；保留失败记录后补齐窗口发布与实际进入 WAITING 的等待，未放宽终止或实际计数断言。

重新安装后，测量驱动先等待本应用无障碍服务实际连接，默认上限 120 秒，可用 -ReadinessTimeoutMillis 在 500～120000 ms 内调整。未就绪只发出 ACCESSIBILITY_REQUIRED 状态，不启动点击；连接后再启动目标页、确认焦点及有效校时，发出 READY 后开始资源采样。超时明确结束，不把授权等待时间计为点击延迟或长等待 CPU。模拟器已验证超时零点击，以及同一测试进程中重连后只收到一次；不据此宣称小米等真机授权流程已通过。
