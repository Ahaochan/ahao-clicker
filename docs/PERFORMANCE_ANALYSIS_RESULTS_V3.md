## 参考方法已发现的限制

40/40 个请求通过独立严格头解析，20/20 对区间相容。完整请求 RTT 的最小值 / P50 / P95 / 最大值分别为 **99.4123 / 107.5633 / 121.6371 / 393.224 ms**。成对保守包络最小宽度为 **107.2493 ms**，P50 为 **115.3049 ms**；宽度不超过 50 ms 的为 **0/20**。

计算包含连接开始前至响应头取得的完整边界，并为时间戳量化保留 ±1 ms；前后区间取包络，不取交集、最小 RTT 或平均。该结果说明当前网络/参考方法无法分辨点击要求的 `[0,50] ms` 窗口，**不是证明产品迟到 100 ms，也不是物理极限**。没有来源时间语义和误差上界认证，即便网络更快也只能作模型条件判断。按计划先停止 R/G 数小时正式来源组，不用应用自己的锚点充当独立真值。

## 授时连接边界的新增证据

两轮各 3 个京东自然请求都有连接前后与采纳记录。03 的第 2 个请求：连接阶段 wall time **6034.3568 ms**，连接前→响应打点 **6632.7843 ms**，产品当前记录的连接后 RTT **598 ms**。原始请求 ID 为 `10105536352-135301-1793175179545`，可在 `pilot-frames-03/app-session/headers.jsonl` 及对应 `sync-boundaries.jsonl` 重放。

这证明现有 RTT 没有涵盖完整连接阶段；连接耗时的全部成因、请求何时真正发送、ID 何时生成尚未取得充分证据。两个边界的中点相差约 3017 ms，**不等于实际时钟就错了 3017 ms**。TLS/DNS、线程等待或宿主暂停不能凭这份稀疏帧轨迹任选一个作结论。应先核验参考边界与来源语义，再决定是否修授时计算；本轮没有修改它。03 另有一条 token=17、缺开始/来源身份的同步错误，保留为未配对原始错误，不混入这 3 个完整 token=19 请求。

历史 `clock-hour` 的 121 个绘制对照估计绝对误差：P50 66、P95 116、P99 121、最大 197 ms，观测中未出现秒级偏差。这只复核了旧版、旧参考方法的历史结果；没有本轮新一小时数据、完整呈现和独立完整边界，不能据此保证今后长期开启始终≤50 ms。
