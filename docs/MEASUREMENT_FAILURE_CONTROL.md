# 失败原因通道的受控验证

日期：2026-10-28。此项在固定A/B探索结束后执行，使用独立目录、ID、测试版本及hash；不改正在采集的APK或驱动。不修改生产调度/安全算法，不替代探索样本，也不补造旧boot的失败原因。

## 需要验证的缺口

纯Kotlin测试已证明失败通道不接收成功事件，观察器异常不改变任务失败及取消结果；off准入证明成功任务写入0条高频事件。还需以实际Android准备/派发路径验证：关闭高频观察时，派发前拒绝能经测量Provider最终状态读出具体原因。

旧boot的FAILED缺少阶段记录，不可恢复其确切原因。这里使用已知干预验证一种真实失败分支，禁止将控制结果自动归因到旧记录。

## 事前固定的两项控制

| 控制 | 条件 | 预期 |
| --- | --- | --- |
| 阳性接收控制 | 同一控制版本、公开滚轮和播放、off、1次、提前4000ms，不施加阻塞 | B点唯一DOWN/UP/onClick、COMPLETED、高频写入0、failureEvent=0 |
| 派发前拒绝控制 | 同一版本及公开流程，在D−500ms安排仅测试版可用的主线程休眠670ms | 准备延迟但仍进入原250ms关闭边界，150ms窗口生效等待后触发原迟到保护；FAILED、failureEvent=107、failureReason=4、无派发、0个目标DOWN/UP/onClick |

拒绝控制记录实际阻塞开始/结束elapsed纳秒，必须证明开始不晚于D−250ms、结束位于D+100～D+220ms。若实际阻塞区间不符合、保护变成EXPIRED或发生其他错误，本控制不通过；保留完整数据，不自行把不同分支当作预期成功、不自动重试。调度仅一次，有界且可取消；测试结束、失败或关闭会话必须移除尚未执行的阻塞任务，不能留给下一会话。

阳性控制前增加待执行任务的取消检查：排入500ms后执行的阻塞，在执行前结束该测量会话，立即以独立后缀ID开启替代会话；等待1200ms后原/替代会话的实际阻塞起止必须均为0、无待执行任务，再执行同一项公开阳性点击。它不施加实际阻塞，不新增性能样本；两个会话的文件都归档。若已执行或泄漏则控制失败，不自动重试。

## 结果要求

- 普通Debug/Release不包含可调用的阻塞入口；仅签名保护的benchmark测量接口可安排，限定off、单任务、无trace和允许的时长/提前范围。
- 在最终状态中保存事件/原因、阻塞真实起止、目标入口计数和原始任务截止；关闭高频观察，不因控制需要安装逐帧字符串监听器。
- 原生产准备、150ms生效等待、250ms迟到拒绝、停止和不重放规则保持。不能为让控制通过降低门槛、去掉安全检查或自动补点。
- 控制报告的passed只表示满足该项预期；拒绝控制0次接收不写成点击成功率。与性能数据及自然失败分别列账。
- 全部控制结束后继续最终功能回归、标准构建、普通清单检查及原APK/偏好/服务/设置恢复，保存证据hash。

## 实际结果（2026-10-29）

两项控制均通过，原始状态/日志/源码/hash保存在本地`controls-20261029`，完整位置见[证据索引](acceptance/2026-10-29-measurement-repair.json)。阳性前的待执行阻塞跨会话取消检查通过，无真实阻塞；随后1次B点DOWN/UP/onClick、COMPLETED、failureEvent=0。拒绝控制真实阻塞D−498.591～D+172.210ms、670.801ms，返回FAILED、event107/reason4，无派发、0个入口。两者off写入均0，质量错误空；不混入探索分母，也不证明旧自然失败是哪条分支。普通Debug/Release均无控制入口；32项功能及进程重建回归、原环境恢复完成。
