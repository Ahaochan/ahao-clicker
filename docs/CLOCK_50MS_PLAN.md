# 50 ms 时钟目标

日期：2026-10-27。

目标是降低悬浮显示相对所选数据源的偏差；不能把画面年龄、网络中点估计偏差和实际点击接收延迟合并成一个数字。50 ms 可作为验收目标，通用 Android 和京东非授时协议不提供每次必达的硬保证。

1. TDD：不与刷新周期对齐地读取实际绘制字符，先复现旧版 100 ms 缓存；画面年龄全量报告，确定性绘制检查验证调用时取时，严格 50 ms 性能由独立 R8 驱动判定。
2. 浮窗随可见绘制帧刷新，最小重绘请求间隔 16 ms，在 onDraw 现场按绝对锚点计算；保留独立任务调度和周期网络同步，隐藏/关闭不刷新，不增加后台线程。
3. 优化构建进行独立外部请求复测，原样保留所有大于 50 ms 的样本及网络不确定度，不以过滤异常样本伪造达标；同时检查 CPU/PSS 代价。
4. 执行完整回归、标准构建与 Lint；根据结果说明已消除的误差和仍无法保证的条件，不提前宣称严格 50 ms 达标。

进展：最终单回调版本严格性能样本 49/181 超过 50 ms，最大 297 ms，未通过；不放宽 50 ms 标准，也不以较早一轮 10/181 结果替代。完整 32 项功能场景、59 个单测、标准构建/Lint 及辅助构建/Lint 通过。最终 30/30 点击实际接收但仍有超过 50 ms 的延迟。证据已归档并恢复普通 Debug；本轮优化与验证工作收尾，严格性能目标未完成。
