# 时间同步与点击功能

## 自动点击页的设置步骤

页面只保留“第一步 · 设置无障碍服务”“第二步 · 设置浮窗”，移除第三步、模式、点位摘要和旧连点表单。两步同时显示颜色和文字：绿色“可用”，红色“不可用”。只有本应用的服务真正连接、系统列出本服务且具备手势能力时才显示可用，不将“系统启用了其他服务”或仅保存了开启设置视为成功。

设置按钮先展示无障碍用途说明，经用户确认再打开系统设置。点击页可见时复用同一个 500 ms 延迟检查，返回应用或切回点击页立即检查；页面不可见时取消，不新增常驻线程或后台服务。同一状态不重复写入文字或颜色。

浮窗使用无障碍专用窗口 TYPE_ACCESSIBILITY_OVERLAY，依赖服务连接，无需 SYSTEM_ALERT_WINDOW，也不以 Settings.canDrawOverlays 误判其可用性。第二步提供“开启定时点击浮窗”和“开启多点点击浮窗”，未连接时引导完成第一步；两个浮窗互斥，重复点击已有入口保持窗口，不启动点击任务。多点不做触摸录制，设置完成后必须点播放。浮窗状态表示窗口权限与服务就绪，时钟隐藏不等于权限不可用。

## 多点点击浮窗（2026-10-30）

定时单点和多点控制浮窗统一使用半透明背景，文字和图标保持清晰。按住左下角或右下角的角标拖动，可改变浮窗宽高；左角固定右边、右角固定左边，最小尺寸保留控制按钮，内容可滚动。准星不跟随缩放，执行中冻结缩放，停止后恢复。两种浮窗分别记忆拖动后的尺寸，关闭重开及重启应用后恢复；恢复时适配当前显示密度与安全区域，自动裁剪不覆盖保存尺寸，不记忆位置。

响应式最小宽度为128dp，按钮始终按播放/停止、加号、移动、关闭的顺序同排，不换行。宽窗按钮为48dp，窄窗收紧按钮宽高、图标和内边距；小时钟按宽高适配字号，定时时间单行自动缩放，小窗隐藏“定时”前缀，点击仍打开滚轮。宽度变化会重算最小高度，不改变任务点位或点击调度。

顶部按播放/停止、加号、四向移动、右上角关闭排列，保留当前时钟而没有定时设置。开启默认一个准星，加号增加新点，中心数字是点击顺序；拖动定位、轻点编辑该点的延迟，默认1000ms、范围0..86400000ms，确认保存、取消不保存。编辑框可删除点位并重新编号，最多50点；独立保存序列，屏幕方向/尺寸变化时不复用旧坐标。

用户明确播放后按序持续循环，直到点击浮窗停止；末点后按第一点的延迟回到第一点，单点也循环。第一点相对播放、后续相对上一点的派发开始，使用单调截止，不将上一手势回调时间机械累加到间隔。手势仍串行；回调已晚于间隔时只执行下一个点，不重叠或补发失败点，零间隔至少让出1ms调度刻度。

运行中编号准星始终可见，保留同一窗口及不透明度，只切换为触摸穿透，禁止增点/编辑。至少150ms输入准备包含在首延迟内，短于该准备时间的首点以就绪为下限；停止后500ms恢复准星编辑。关闭、模式切换、屏幕关闭和服务断开取消待执行动作及恢复回调，不自动恢复任务。相对派发时刻不等于目标实际DOWN，验收单列真实接收顺序与间隔，不承诺硬实时。

## 双页签与内置时间源（0.2.0，2026-10-26）

主页面分“自动点击”“时间同步”两个页签。自动点击页保留权限、定时和多点浮窗入口；时间页负责来源比较与校时配置，不再从点击表单中混入校时入口和详情。时间页按两列显示京东、淘宝、阿里云、腾讯云、Cloudflare，主标题为来源名称，下一行显示 HH:mm:ss:SSS(+800)，正值表示领先本机的毫秒数；窄屏、大字体允许折行。

点击卡片选择任务与悬浮时钟的参考；间隔使用数字输入，范围 1000～86400000 毫秒，默认 60000 毫秒，保存前校验，错误不覆盖已保存值。HTTPS 来源至少间隔 1000 毫秒；NTP 来源保留 60000 毫秒的请求下限，界面明确说明。没有 URL、格式、字段等用户输入，也没有周期同步开关。任务执行中禁止修改来源和间隔。

京东使用 OPTIONS https://api.m.jd.com，读取 X-API-Request-Id 的末段毫秒时间戳，不依赖旧 JSON 接口和响应体；校验完整的三段数字结构、13 位尾段及与 HTTP Date 的差值不超过 2000 ms。缺失、畸形、日期不一致或 Age 非零的响应不采纳，也不回退为 Date 或其他来源。该字段表示网关请求时刻的实测推断，不是有精度承诺的授时协议。请求计时从 Android 完成连接准备后开始，避免把 DNS/TCP/TLS 建连耗时当成网络往返；在解析前记录接收时刻，随后按单调时钟中点建立参考。

淘宝适配 mtop.common.getTimestamp 的 data.t 字段，兼容字符串毫秒时间戳。HTTPS 采用正常证书与主机名校验、禁止重定向及缓存；JSON 请求增加标识且响应限制 64 KiB，京东仅读取响应头，不分配 JSON 响应缓冲。阿里云 ntp.aliyun.com、腾讯云 ntp.tencent.com、Cloudflare time.cloudflare.com 仍使用轻量单播 SNTP，UDP 123。校验响应来源、版本、模式、闰秒同步标记、层级、请求标识、接收/发送时间及往返耗时，拒绝无效和 Kiss-o'-Death 报文，支持 2036 年纪元转换。SNTP 不提供 NTS 身份认证。不修改系统时间，不创建 NTP 守护进程。

time 功能包集中管理独立来源状态，共用至多两个网络工作线程；一个来源失败不会覆盖其他来源样本。仅时间页可见时观察所有来源，切走后只维护有页面、任务或时钟需要的选中来源，全部关闭后暂停。各源样本只在内存中；切换后只读取该源自己的样本，不把旧来源或本机时间冒充新来源。数字每 100 毫秒以单调时钟推算最后成功样本，失败时保留并标记上次样本，超过 5 分钟标为过期，首次失败直接显示同步失败。

DNS 等待与 UDP 接收分别最多 2 秒，HTTPS 连接/读取超时各 3 秒；样本往返超过 2 秒不采纳。API 29+ 使用可取消的系统异步 DNS，API 26–28 使用共享的单线程有界后备。取消关闭网络并以代次拒绝旧响应。请求按开始时刻计算间隔并结合各来源最低间隔，不补发堆积请求；无观察者时取消回调和网络。定时单击启用时要求最近 5 分钟内有效样本。

当前网络的逐源可达性见验证记录；往返时间不是时间误差或点击精度保证。

## 准星、定时单击与悬浮时钟

每次新开定时浮窗，开始时间默认取打开时当前所选来源的时间参考（含毫秒），覆盖旧触发时刻；未有外部样本时初值取本机时间，但启用仍要求有效校时。默认值是固定草稿，不随当前时钟滚动，也不自动点击。点击时间后四列滚轮从草稿值开始供微调；确认仅保存。已打开的浮窗再次点入口不会重置修改，关闭再开重新取当前时间。默认值通常在播放时已过期，沿用现有滚轮确认流程，不补发过期点击。

标题栏从左到右为播放/停止、四向拖动、关闭。播放使用可见准星和已配置的未来触发时刻，真正启用定时后显示方块停止图标；再点停止取消待执行任务、恢复播放图标并保留浮窗。停止后可修改下一次开始时间，重新开启必须由用户再次点击。任务完成、失败或过期也恢复播放，过去的时刻不能补点。时间未设置或已过期时打开四列滚轮，确认后开启，取消保持停止；缺少有效校时、点位越界或控制窗覆盖目标时仍拒绝开启并给出短提示。

每次切换显示“自动点击已开启”或“自动点击已关闭”的 Toast 样式短提示，重复点击刷新为最新提示，2 秒后消失。提示位于现有浮窗内容层，不改变窗口大小或触摸边界，不盖住顶部控制按钮。后台系统 Toast 会在应用通知关闭时被压制，且存在限频（[Android 源码](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/services/core/java/com/android/server/notification/NotificationManagerService.java)、[Toast API](https://developer.android.com/reference/android/widget/Toast)）；因此浮窗按钮使用窗内提示，不为此请求通知权限，窗口不可用时仍尝试系统 Toast。

当前悬浮时间下方以 20 sp 显示“开始点击”和所选 HH:mm:ss:SSS，主时钟为 26 sp；未配置显示“未设置”。该值是计划触发时刻，不是点击播放按钮的时刻。点击该时间块打开浮窗滚轮，确认只保存、不启动；有效时间直接播放，过期或未设置时从播放进入滚轮则确认后开启。时间块带编辑图标和读屏说明，启用中须先停止再修改。首页移除时间设置与准备入口，启用时与本次任务目标保持一致；格式化只在配置变化时执行。

悬浮时钟和准星/定时控制窗在标题栏右上角显示“×”关闭图标，触摸区域为 56×56 dp，提供“关闭悬浮时钟”或“关闭浮窗并停止任务”的无障碍说明。图标固定在滚动内容之外；独立时钟移除底部文字关闭按钮。关闭控制窗会停止当前选择或任务，取消后不补点；定时浮窗不再显示“隐藏时钟”“启用定时”“停止定时”三个文字按钮，任务由顶部播放/停止控制；时钟始终显示，准星不再需要单独定位或确认按钮，拖动结束自动保存。录制/连点的原有停止控制继续保留。

标题栏拖动入口使用四向箭头十字矢量图标，不显示“拖动时钟或控制条”文字；保留原有整块拖动区域和 56 dp 高度，读屏名称为“拖动浮窗”。拖动不会触发目标点击；启用后控制条仍锁定，准星独立保持可拖动。

第二步点击“开启定时点击浮窗”，同时显示时钟与可拖动准星；当前屏幕有有效历史点位则恢复，否则从屏幕中心开始。主页面移除单独的定位按钮，不需要确认。准星中心为屏幕像素坐标，拖动只移动准星、消费触摸，不向下层注入手势；松手自动保存当前屏幕标识和位置，不再显示坐标摘要；首页 500 ms 检查仅更新服务就绪状态和入口可用性。浮窗不再显示坐标、倒计时或持续任务状态；完成/失败以图标复位和短提示表达。

定时等待时可拖动准星。截止前约 250 ms 保存最后可见中心并收起准星，让输入窗口提前移除；最后这段时间不可拖动。平台为输入窗口切换保留移除后至少 150 ms 的准备余量，正常情况在截止前已完成，迟到准备只等待剩余时间，并继续检查 250 ms 迟到关闭边界。核心到点消费一次资格，使用最后可见中心并检查控制窗覆盖、锁屏和边界，最多派发一次。完成/取消/拒绝/超时后保留有界恢复回调，通常完成后 500 ms 恢复同一准星；停止准备可取消并恢复，关闭或断开使恢复回调失效，不重建任务、不补点。旋转仍停止并要求重新开启。

屏幕标识使用物理尺寸与旋转，Activity 与无障碍服务不再依赖各自的资源方向值。没有物理变化的配置回调不清空准星；真实旋转或尺寸变化仍停止任务并作废原位置。旧版标识升级后需重新拖动定位一次。

准星为 FPS 风格四段短线、中心留空和小点，采用明亮绿与深色描边，保留 64 dp 透明拖动区域；不引入位图或动画。

定时单击只选择时、分、秒、毫秒，同一行四个滚轮分别覆盖 00–23、00–59、00–59、000–999，不选择年月日、不弹键盘。确认时按所选时间源的当前参考确定下一次到达：未到为今天，已过或恰好相同为明天；保留设备本地时区。确认后保存一次性的绝对目标，显示 HH:mm:ss:SSS，取消不保存。已启用任务不会自动续到次日，执行、停止或过期后仍须用户显式开启；过期目标须重新选择。夏令时不存在的时刻跳过，重复时刻取下一次实际发生的时间。横屏使用较矮的原生滚轮，说明文字可纵向滚动。

在目标页面点击浮层顶部播放图标（缺少有效时间时选择并确认），固定最多派发一次 1 毫秒点按；系统输入采样与目标处理仍可能延迟 DOWN 和 onClick。核心在调用平台前消费本次资格，重复定时回调、完成/拒绝/超时、停止、断连和进程重建都不能补发。若调度线程错过目标超过 250 毫秒，任务过期结束；这是停止迟到补发的边界，不是精度保证。

距截止超过 5 秒时，采用同一来源较新且新鲜的样本重算绝对单调截止，旧定时回调随即作废；最后 5 秒锁定同一参考供时钟和任务使用。校正超过 1000 ms 或突然跨入最后 5 秒会停止；目标已过则结束，不补发。启用和截止准备均要求有效校时，变更来源停止任务。时间只通过锚点加单调时间差计算，不累计刷新间隔。悬浮时钟可单独开关；等待时保留顶部停止和关闭图标。悬浮数字在实际绘制时取时，最小重绘请求间隔 16 ms，本轮 60 Hz 模拟器通常约 30 帧/秒；状态轮询仍为 100/33 ms，生命周期与完成检查最多每 250 ms，关闭浮窗停止续约绘制。严格 50 ms 上限未通过本轮外部对照，见 [记录](CLOCK_50MS_RESULTS.md)。点击调度与显示刷新独立，不按毫秒发网络请求或忙等待。顶部停止图标位于滚动内容之外。

完成回调只显示手势完成，不能证明目标业务成功。停止只取消未来派发，不能撤回已经注入的手势或目标队列中的处理。锁屏、熄屏、服务断开、时区/系统时间变化、显示尺寸变化会结束任务，不自动恢复。

## 历史引擎：点击时间窗与次数

以下为保留的底层连点/多点规则，当前没有公开配置入口，回归测试通过服务接口构造任务，不代表新录制浮窗已开放。开始包含、结束不包含；过去的开始时刻立即开始，已结束的时间窗拒绝启动。其次数和时间窗不会带入定时单击。

任务开始时冻结应用内时间参考，后续同步和用户修改设备时间不让已启动任务跳时。没有成功外部样本时明确显示使用设备时间。等待采用系统回调，不忙等待，不承诺硬实时或休眠唤醒。

每一行表示 x,y,点击前等待毫秒，坐标是当前显示屏像素：

```text
300,600,100
500,700,250
```

一行表示单点连点，多行按顺序循环。任务首个点在开始时刻执行，忽略首步等待；后续动作等待其对应行的间隔，以上一手势完成回调为基准。在多点循环中再次遇到第一行时，该行间隔会生效。当前每次点按持续 40 毫秒。

总点击次数指手势完成次数，不是循环次数。达到次数、时间窗结束或出现拒绝/取消/超时，任一条件都会停止，不补发积压点击。若剩余时间已不足完整手势时长，不再派发该手势。

完成回调只证明系统手势完成，不能证明目标应用已处理业务动作。时间窗不足时可能少于目标次数，完成手势数仅用于引擎状态与回归核对。

## 历史引擎：录制并实际点击

本版不实现新多点录制浮窗，首页入口禁用。以下仅记录现有引擎行为；验收由测试直接调用服务，不提供面向用户的录制流程。

1. 测试启动录制后，本点击器退到后台。先显示“准备录制”，等待 600 毫秒给页面切换让出时间，期间触摸不采集、不注入；提示“正在录制”后开始点选。这是切页缓冲，不是目标接收保证。
2. 采集层消费用户点按，在输入事件确认后，将同一窗口临时设为完全透明且不接收触摸，避免反复拆装输入通道。
3. 等待窗口更新与 200 毫秒缓冲，再通过无障碍接口在该坐标执行真正的点击。
4. 系统完成回调后保存该点，缓冲 500 毫秒再恢复采集层。记录上次手势完成回调到本次实际派发的等待时间；这段等待包含窗口切换缓冲。
5. 用旧引擎“结束录制”或“停止”关闭浮层；测试读取录制步骤并构造间隔，当前首页不提供逐行编辑。

不被动监听其他应用的原始触摸，不使用截图、录屏或页面内容读取。拖动、长按、多指触摸不作为录制点。注入失败、取消、超时的点不会写入任务。录制过程中真实执行的点击可能触发目标页面动作，用户在启动录制前已明确选择此功能。

显示“正在执行点击”时，应等提示消失且录制层恢复后再录下一点；暂停采集期间的触摸会直接作用于下层页面，不会写入步骤。当前录制适合逐点操作，不保证快速连续触摸的无损采集。缓冲仅用于录制，编辑后的回放按配置间隔执行。完成回调仍不等于任意目标应用已处理业务动作，不能靠重试注入补偿，否则可能重复操作。

停止后不再派发下一次手势，已派发的手势可能仍需结束；新任务等待当前手势完成，防止互相取消。屏幕尺寸/方向变化、锁屏、熄屏或服务断开会停止当前任务，不自动恢复。

## 资源与验证

- 点击重复按索引计算，不展开次数列表；核心最多保留两项待调度回调。
- 录制最多 500 个点，编辑文本最多 64000 字符；网络响应和日志不无界增长。
- 来源网络共用最多两个工作线程；点击与浮层在主线程串行处理。进度最多每 250 毫秒刷新，Activity 不可见时停止刷新；时间比较数字每 100 毫秒更新，离开页签即取消。
- 核心测试使用虚拟时钟与队列，不依赖真实等待。覆盖时间窗边界、次数、多点间隔、拒绝/取消/超时、陈旧回调、录制完成状态和输入上限。
- Android 层补充时间响应解析测试，覆盖 HTTP Date、JSON 路径、单位换算、溢出及异常输入。
- 模拟器通过独立接收应用核实连点、多点顺序、录制真实点击、12 次连续逐点录制和取消后的陈旧回调；同时验证旋转、熄屏、服务断开及进程重建不恢复点击。
- 真实内存、吞吐、抖动和目标接收数必须在真机优化构建中测量。历史版本记录过同机优化包资源对比、20 次实际多点接收及约三分钟时钟观察，旧公开表单验收脚本当前暂停，本轮未重测真机性能；方法和边界见 [PERFORMANCE.md](PERFORMANCE.md)。

设备验收至少包括：首次启用/拒绝权限、实际录制点按、修改每步间隔、定时开始、截止停止、浮动停止、旋转/熄屏/服务断开、外部同步失败与恢复、进程重建后不自动恢复点击。
