## 结论与执行约定

当前`app → core`依赖方向正确，core没有依赖Android。点击执行器通过`DelayScheduler`、`GestureDriver`及时间函数隔离平台，这些边界继续保留。

下列问题主要增加维护、测试和回归风险。没有证据表明保留它们会造成点击延迟，也不能承诺重构后降低延迟。用户决定暂不单独重构：后续修改相关功能时先查看本清单，在同一职责范围内逐步整理。仅修改文案、图标或无关修复，不必扩大为架构改造。

P2/P3表示本次审查的相对优先级，不表示已经发现运行故障。继续保持Android-only、app/core两个模块和少量普通类/接口，不为形式增加DI框架、空模块或额外线程。实际实施前更新PLAN，并按当前需求复核本记录；下方位置以类和方法为准，行号可能随代码变化。

## 实施与验证要求

1. 一次处理一个相关边界，先保留现有行为测试，再补可证明问题或边界要求的测试；行为修复遵循失败测试→实现→回归。单纯提取保持既有调度、线程、缓存和资源生命周期，不同时调优算法。
2. A1覆盖时间缺失/过期时的滚轮确认、分秒毫秒记忆、单次执行、最新准星位置、校时更新与最后5秒锁定、取消和旧回调失效。系统反馈中断保留浮窗；真正断开、锁屏/熄屏、实际显示变化继续停止且不恢复。结合[录屏案例](RECORDER_OVERLAY_DIAGNOSIS.md)回归。
3. A2覆盖活动任务禁止变更、参数上下界、保存与应用、来源独立样本和节流、页面退出后的订阅清理。A3覆盖默认延迟、顺序循环、草稿恢复、播放快照、准星可见与触摸穿透、停止恢复编辑、旧对话框/回调失效及两种浮窗互斥。
4. A4覆盖现有接口解析和坏样本拒绝、取消与旧请求失效、来源选择及持久化兼容、独立节流；迁移前后相同输入产生相同有效时间参考。
5. 实施代码变更后按AGENTS.md运行适用的核心/应用单测、Lint、Debug/Release及针对性设备回归。若触及截止调度、输入准备、手势派发或校时路径，使用相同条件的优化构建对照：中位数、P95、P99、最大延迟、实际接收率和超限次数/总次数，缺失与不可判定分列。无条件重测时明确留下未验证项，不以架构变整洁证明性能达标。
6. 完成后在本清单及PLAN标记对应编号，链接实现和验证记录；未处理部分继续保留，不把“已经记录”标成“已经修复”。
