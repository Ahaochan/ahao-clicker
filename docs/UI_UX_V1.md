# 阿浩点击器 UI / UX 方案 V1

日期：2026-10-25。状态：设计草案，待讨论；本轮不实现界面代码。

后续用户已明确五项下一版重点，范围以 [UI_UX_V2.md](UI_UX_V2.md) 为准。本草案中的自填时间源、可重复的指定时刻模式和多点列表重构优先级已被修订；保留本文作为早期设计讨论记录。

## 1. 设计方向与范围

把产品设计成轻量的操作工具：打开后能配置点击，在目标页面明确启动，执行中随时能停。视觉重点是点位顺序、点位之间的等待和任务时间窗。

本版围绕一个当前任务，覆盖单点连点、多点录制与回放、外部时间同步。暂不设计多任务库、账户、云同步、脚本市场、长按和滑动。已有配置继续复用；不为界面升级增加后台常驻任务。

本文中的单点选位、结构化步骤编辑、执行前准备态、时间选择器和浮层拖动均为拟新增交互。当前 MVP 仍是动态表单与已有录制浮层，不能将草案视为已经实现。

## 2. 信息架构

```text
阿浩点击器
├─ 点击任务（默认页）
│  ├─ 单点连点 / 多点步骤
│  ├─ 点位与间隔
│  ├─ 总次数与运行时间窗
│  └─ 准备执行 → 目标页面浮层确认 → 执行状态 / 本次结果
├─ 时间同步
│  ├─ 当前参考与上次成功时间
│  ├─ 一个生效的外部时间源
│  └─ 来源编辑、立即同步、周期同步
└─ 右上角设置
   ├─ 点击服务状态与开启引导
   ├─ 跟随系统 / 浅色 / 深色
   └─ 使用说明与版本
```

只有两个主要页面，使用顶部标签切换，底部留给当前页面的主要操作；V1 不增加底部三栏导航。切换标签保留输入和滚动位置。未配置外部时间源时，普通点击仍可使用设备时间。

## 3. 视觉规范

视觉风格为清晰、紧凑的工具界面。使用平面分区和少量分隔线，主要按钮用蓝色实底；停止按钮始终用红色实底。页面辨识点是多点步骤中的顺序线，以及开始、截止两个明确端点。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | #F4F6F9 | #111820 |
| 内容面板 | #FFFFFF | #1B2531 |
| 主要文字 | #182538 | #E7EDF5 |
| 主操作、选中、完成 | #2457C5 | #A9C5FF |
| 等待注意、使用旧参考 | #8A4B00 | #FFD69A |
| 停止、无效输入 | #B3261E | #FFB4AB |

这些是候选颜色，实施时对每组实际文字和背景验证对比度。状态同时配文字和图标，不能只用颜色区分。

- 标题 24sp，分区标题 18sp，正文和输入 16sp，辅助说明 14sp。
- 中文与按钮用系统 sans-serif；时刻、毫秒和坐标用系统等宽数字，避免数字变化造成跳动。不打包字体文件。
- 页面边距 20dp，间距以 8dp 为基准，普通行至少 56dp，主按钮至少 52dp，圆角约 12dp。
- 控件触摸目标至少 48×48dp；小号正文对比度至少 4.5:1。依据 [Android 无障碍设计建议](https://developer.android.com/guide/topics/ui/accessibility/apps)。
- 支持字体放大、深色模式、横屏及系统栏安全区域。大字体时允许分行和纵向增长；停止按钮不能被截掉。
- 不做呼吸灯、持续闪烁或背景动画。状态变化用简短反馈；尊重系统减少动画设置。

## 4. 点击任务页

### 4.1 单点连点

以下为已经选定点位后的状态；首次使用时位置为空，显示“选择位置”，不预填可能误点的坐标。

```text
┌────────────────────────────────┐
│ 阿浩点击器                设置 │
│ 点击任务 ━━━━━     时间同步     │
│ 点击服务已连接                 │
│                                │
│ [ 单点连点 ]   多点步骤         │
│                                │
│ 点击位置                       │
│ 点 1 · X 300 / Y 600   [重选]  │
│                                │
│ 点击间隔             200 毫秒 > │
│ 每次手势完成后，再等待此间隔    │
│                                │
│ 总点击次数               10 次 │
│                                │
│ 开始方式   [手动启动] 指定时刻  │
│ 最长运行时间              10 秒│
│ 次数或运行时间先到即停止        │
│                                │
│ 时间参考：设备时间     [去校时] │
│────────────────────────────────│
│          [ 准备执行 ]          │
└────────────────────────────────┘
```

- 点位选择：点击“选择位置”先显示准备浮层，用户切到目标页面后点“开始选点”，再点选位置；点一下只标记坐标，确认后保存，不注入点击，始终提供取消。坐标的手动输入保留在位置编辑的高级项中。
- 间隔采用数字输入和明确单位，提供 100/200/500 毫秒、1 秒快捷项，也可自定义。0 表示不额外等待，仍需手势与系统处理时间，不显示“零延迟”等承诺。
- 次数为总手势次数，允许正整数；不显示“轮数”输入，以免与总次数混淆。
- 普通操作使用手动启动：点击浮层“开始”时确定开始时刻与最长运行截止时刻。此时首点立即派发。
- 草稿在离开输入项或页面时保存；保存草稿不会启动点击。清空任务放在菜单中，需确认，并保留当前任务直到用户明确替换。

### 4.2 指定时刻

```text
开始方式      手动启动 [指定时刻]

开始  2026-10-25  21:00:00.000  >
截止  2026-10-25  21:00:10.000  >
      10 秒时间窗 · 设备本地时区

本次参考：外部时间
上次同步 8 秒前 · 比设备时间快 125 毫秒
```

日期与时间分开选择；时间包含时、分、秒及可选毫秒输入。默认显示毫秒 000，保留精确输入能力。跨日时显示完整日期，不隐式把较早的截止时刻解释为明天。时区显示设备实际时区，例如 Asia/Shanghai，而非固定写入。

校验发生在字段旁：截止不晚于开始、窗口已结束、点位越界、次数无效分别显示具体原因。定时任务如果已错过开始时刻，要求重新设时，不静默改成立即执行。这是拟调整的产品行为，实施时需补充相应测试。

### 4.3 多点步骤

```text
┌────────────────────────────────┐
│ [ 单点连点 ]   [多点步骤]      │
│                                │
│ 点击步骤 · 共 3 点  [录制点位] │
│                                │
│ ① 点 1                 编辑 ⋮ │
│ │ X 300 / Y 600                │
│ ├ 完成后等待 250 毫秒       >  │
│ ② 点 2                 编辑 ⋮ │
│ │ X 500 / Y 700                │
│ ├ 完成后等待 500 毫秒       >  │
│ ③ 点 3                 编辑 ⋮ │
│   X 400 / Y 900                │
│ ↳ 等待 150 毫秒，回到点 1   >  │
│                                │
│ 总点击次数              10 次  │
│ 按点 1→2→3→1…，总共执行 10 次 │
│ 开始方式、时间窗、参考时间…    │
│────────────────────────────────│
│          [ 准备执行 ]          │
└────────────────────────────────┘
```

间隔画在两个动作之间，避免用户猜测“这一行的间隔属于哪个点”。首轮点 1 不等待；循环回点 1 时使用底部回环间隔。内部仍可映射为现有的下一步 waitBeforeMillis，无需改变核心调度语义。

点击间隔行可编辑；点击步骤可编辑坐标；菜单提供上移、下移、删除。等待间隔跟随其目标点移动：一个点的进入前等待显示在它前面的连接线上；重排为首点时，这段等待显示在回环边上，首轮忽略。重排后立即更新全部连接线，保存前可以核对顺序和回环。删除步骤不撤销目标应用中已经发生的操作。500 点上限显示在录制计数中，长列表按可见行复用。

从多点切为单点时，提示选一个点用于连点；未确认前不丢弃多点草稿。替换已有点位的录制先确认，原步骤保留至新录制明确保存。

## 5. 录制流程与浮层

```text
任务页点“录制点位”
      ↓
说明：本次录制会真实点击目标页面
[取消]  [进入录制准备]
      ↓
准备浮层：尚未采集、尚未注入点击
用户切到目标页面并摆放控制条
      ↓ 点“开始录制”
可以录点 → 本次执行中 → 可以录下一点
      ↓ 点“完成录制”
停止采集、保存步骤、返回编辑
```

准备态不拦截目标页面触摸，也不录入用户切换应用、滚动和导航的操作。只有明确开始录制才显示采集层。

```text
可以录点                         正在处理本次点击
┌─────────────────────┐         ┌─────────────────────┐
│ ⠿ 录制中 · 3/500 点 │         │ ⠿ 正在执行第 4 点   │
│ 可以录下一点        │         │ 请等待，勿继续点按  │
│ [完成录制] [停止]   │         │ [完成录制] [停止]   │
└─────────────────────┘         └─────────────────────┘
```

- 两个状态使用固定宽度、固定预留文本高度，按钮位置不跳动；文字和图标明确改变，颜色只作辅助。
- 处理期间“完成录制”暂不可用，“停止”保持可用。提示持续到采集层实际恢复，不按一个估算倒计时提前宣告可点。
- 明确说明：等待时额外触摸可能直接作用于目标页面且不会录入。当前引擎不支持快速连续触摸的无损录制，界面不能制造“所有触摸都会记录”的印象。
- 录制间隔包含采集与派发处理等待。回到步骤编辑时提示一次“已保留录制间隔，可逐项调整”，不把它包装成原始物理触摸时间。
- “完成录制”保存已完成点并返回编辑；“停止”立刻停止调度、保留已完成点，停留在目标页面。取消和失败均不撤销已发生的真实操作，不重试注入。
- 控制条只通过独立拖动把手移动，移动把手不会成为录制点。定位时避开系统栏和屏幕边缘，运行后锁定位置；停止按钮不折叠为小圆点。
- 准备执行前检查控制条是否覆盖计划点位；有覆盖时要求挪开后再启用。录制中控制条区域不参与录点。

## 6. 准备、等待和运行

应用内“准备执行”只检查配置并显示浮层，不立即点击。用户切到正确页面，再通过浮层确认开始；不依赖读取目标应用内容来猜测页面是否正确。

```text
已准备，尚未开始                 已启用定时
┌──────────────────────┐        ┌──────────────────────┐
│ ⠿ 单点 · 10 次       │        │ 等待 21:00:00.000    │
│ 间隔 200ms · 最长10s │        │ 还有 00:12.4         │
│ 确认目标页面后开始   │        │ 外部时间 · 本次已固定│
│ [开始] [取消]        │        │       [停止]         │
└──────────────────────┘        └──────────────────────┘

执行中                         本次结束
┌──────────────────────┐        ┌──────────────────────┐
│ 手势完成 12/100       │        │ 时间窗已结束         │
│ 当前第 2 点          │        │ 手势完成 37/100      │
│       [停止]         │        │ [返回编辑] [关闭]    │
└──────────────────────┘        └──────────────────────┘
```

定时任务在准备浮层使用“启用定时”按钮，启用时重新检查是否错过开始时刻。手动任务使用“开始”。这两者都是用户明确授权执行的最终入口，不能因回到应用或服务重连而自动触发。

停止单击生效，不显示二次确认；已注入的手势可能仍会结束，文案不承诺撤回既有点击。不提供 V1 尚未实现的“暂停/继续”，防止与绝对时间窗和旧任务恢复产生歧义。

运行中应用页切为只读任务摘要和停止入口；本次完成后再编辑。返回键和切换应用不等于停止，屏幕上持续保留浮动停止。屏幕旋转、熄屏、服务断开后的停止原因显示在本次结果里；不自动恢复，也不出现能恢复旧计划的按钮。

“手势完成”沿用系统完成回调语义；详细说明中写“是否在目标页面生效，请以目标页面为准”。不把派发数显示为“点击成功数”，不展示没有测量依据的精度或成功率。

## 7. 时间同步页

```text
┌────────────────────────────────┐
│ 阿浩点击器                设置 │
│ 点击任务       时间同步 ━━━━━  │
│                                │
│ 当前时间参考                   │
│ 外部时间 · 已同步              │
│ 21:00:00.125                   │
│ 比设备时间快 125 毫秒          │
│ 上次成功 8 秒前                │
│                                │
│ 时间来源                 [编辑]│
│ https://用户配置的地址/…        │
│ JSON 毫秒 · data.timestamp      │
│                                │
│ 自动同步                   开  │
│ 同步间隔                 1 分钟│
│ 每次请求结束后等待该间隔        │
│                                │
│ 最近状态：同步完成             │
│ 往返耗时 46 毫秒               │
│────────────────────────────────│
│          [ 立即同步 ]          │
└────────────────────────────────┘
```

未配置时显示“使用设备时间”，主要操作为“配置时间源”；不预填或自动访问公共时间服务。编辑来源在独立表单中完成：HTTPS 地址、读取方式、JSON 字段路径、同步间隔。HTTP Date 隐藏 JSON 路径；JSON 模式明确区分秒与毫秒。

来源编辑采用草稿，点击“保存”才生效，离开时提示放弃未保存更改。保存新的地址/格式/字段会清除旧参考，并提示“新来源尚未同步”，由用户立即同步或开启自动同步。自动同步只对已保存的有效配置开启；间隔可选 10 秒、1 分钟、5 分钟或自定义，沿用 1 秒至 24 小时边界。

同步失败时保留上次成功时间并明确区分最近请求状态：

```text
最近一次同步失败                 [重试]
仍使用上次成功参考 · 2 分钟前
原因：服务器返回 503
```

未成功过则显示“尚未同步，使用设备时间”。HTTP Date 标为“秒级来源”；RTT 标签为“往返耗时”，不换算成精度承诺。请求中禁用重复点击同步，结束后恢复按钮。

若新任务将使用失败前的旧参考，在最终启用时额外说明“最近同步失败，将使用 2 分钟前的参考”，让用户明确选择继续或返回校时。本次任务启动后参考固定；后续校时不跳变本次开始/截止时刻。执行期间允许立即同步或关闭周期同步，但来源编辑暂不可用，避免用户误以为能改变正在运行的任务。

## 8. 权限与异常反馈

| 场景 | 反馈与下一步 |
| --- | --- |
| 服务未开启 | 保留编辑能力；准备时说明用途，提供“前往开启”；返回后检查连接，但不自动开始 |
| 设置已开但服务未连接 | “点击服务尚未连接”，提供检查设置；不只显示一个绿色开关 |
| 点位为空或越界 | 在位置项下说明问题，提供重新选点 |
| 时间窗无效或已错过 | 聚焦对应时间项，提供重新选择，不静默执行 |
| 录制注入拒绝、取消、超时 | 停止录制并保留已完成点，说明最后一点未保存，不自动重试 |
| 屏幕旋转、熄屏、服务断开 | 停止并说明原因，需用户重新准备任务 |
| 完成次数少于目标 | 显示具体停止原因，例如“时间窗已结束”，不误报为全部完成 |
| 删除已录步骤或重录 | 说明只修改计划，不能撤销目标页面已经发生的操作 |

字段错误留在字段旁，重要状态留在页面或浮层中；Toast 只用于非关键的短反馈。该方案沿用无障碍浮层，不新增截图、屏幕内容读取或通用悬浮窗权限申请。

## 9. 实施与验收建议

先将静态表单与组件迁入 XML / View Binding，使 IDEA 能预览完整编辑页。维持 app/core 边界，不为视觉升级引入 Compose、字体包或动画框架。步骤列表按可见内容复用，数字刷新不反复创建整个表单；实际 PSS 与流畅度继续用优化构建验证。

准备态、单点选位、草稿保留、具体失败原因和结果摘要需要补齐状态与数据支持，不能仅靠更换控件文案实现。失败原因应来自真实错误分类，不能把当前的失败布尔值推测成某个具体原因。

建议按以下顺序实施，均待用户讨论方案后再开始：

1. 两个主页面、视觉资源、结构化输入、时间选择与字段错误。
2. 单点选位、步骤与回环间隔编辑、草稿保存及模式切换。
3. 准备态、录制状态、可拖动控制条、覆盖点位检查与最终启动入口。
4. 状态与边界验收：服务连接、过期开始时刻、停止、未保存更改、重录取消、间隔重排映射。

界面验收使用 360dp 和 411dp 竖屏、横屏、浅/深色及大字体；检查键盘不遮住当前输入，停止入口始终可见。功能验收继续以独立目标的实际接收事件为准，并增加“保存/准备/授权返回不点击、单点选位不点击、录制明确真实点击、停止后不恢复”的测试。

方案讨论优先确认：两个页面的信息组织、准备后再从浮层启动的流程、单点选择与多点录制的区别，以及用步骤间连接线编辑等待间隔的表达。
