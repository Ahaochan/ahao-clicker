# 调度与调用栈证据采集计划

日期：2026-10-27。Goal：先采集数据，再分析超过 50 ms 的显示/点击样本，不先修改运行算法。

状态：采集与分析 Goal 已完成，见 [结果](PERFETTO_RESULTS.md) 和 [证据](acceptance/2026-10-27-perfetto-analysis.json)。本轮没有实施生产优化，严格 50 ms 指标仍未通过；目标栈缺失与首轮未启用失败的原因明确保留为未知。

1. 核对模拟器、Perfetto 数据源、分析器版本。只在 benchmark Manifest 增加 profileable，保留 R8 优化，不向普通 Debug/Release 添加此声明或测量接口；普通 Debug 本来就可调试。
2. 先做短采集，确认线程调度、帧时间线、CPU 调用栈均实际存在，并检查丢包、展开失败与采样开销。不能把空轨迹写成已经完成分析。
3. 采集静态悬浮时钟与实际点击两种负载，同时保存独立时间对照/目标接收记录、CPU/PSS、APK 与 R8 mapping 指纹、配置和原始 trace。增加同一测量包不带采样的对照，不假定不同网络窗口完全可比。
4. 完成采集后用 Trace Processor 查询：CPU 热点、主线程/渲染线程状态、帧延迟、截止至派发/接收间的运行与等待、来源参考误差；用原始调用栈生成火焰图。未知部分明确写为未证实。
5. 保存可重放分析脚本、SQL、报告与证据索引，恢复原配置和普通 Debug，保留 IDEA 内嵌模拟器。先交付分析结论，本 Goal 不以达到 50 ms 或实施优化为完成条件。

所有 trace 限定应用测试场景与有界时间，不采集账号页面、堆转储或网络正文。采样会改变负载，模拟器结果不替代真机；CPU 火焰图比例不等于单次请求的墙钟延迟。
