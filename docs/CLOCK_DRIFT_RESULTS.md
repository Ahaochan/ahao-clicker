# 悬浮时钟长期偏差验证

日期：2026-10-27。状态：本轮模拟器验证完成，已修复复现问题；真机未测。

## 已确认的问题与修复

旧版的 RESULT 状态一直使用任务自己的 TimeReference。定时结束后浮窗可以保留很久，即使后台同步成功，显示也不采纳新参考。可控 HTTPS 源前移 4000 ms 后，旧版 Canvas 使用的数字落后 4048 ms。修复仅让仍在等待/执行的任务使用任务参考；完成、失败、过期后的浮窗改用最新来源参考，不会恢复点击。

RED/GREEN：同样的来源前移 4000、后移 4000、回到零的用例，完整回归中显示估算偏差分别为 -82、-79、-70 ms，目标只接收最初一次点击。主页后台时，周期同步跟随外部跳变；断网后自动恢复无需手动同步，恢复后 -76 ms，零点击。

## 独立对照方法

使用 API 37 x86_64、1080×2400、SwiftShader 及现有 IDEA 内嵌模拟器。只安装可选 R8 benchmark 测量包，正式 Debug/Release 没有测量 Provider。测试进程与应用进程独立，应用不附加 Instrumentation/调试器。

应用使用京东 OPTIONS 来源，每 60000 ms 定时同步。主页面退到后台，时钟浮窗自己保有来源观察者。测试进程每 30000 ms 另外发送 OPTIONS 请求，自行解析响应末段时间戳，用请求 RTT 中点折算到读取时刻；这个请求不更新应用参考，也不触发同步。拒绝非 2xx、缓存 Age、非法请求 ID 和 RTT > 2000 ms 的对照样本，失败样本也保留。

只读观察真实 View 绘制遍历中 Canvas 使用的字符和绘制时刻，不强制刷新/绘制，不使用故意降到 1 Hz 的无障碍描述。该观测到应用绘制遍历为止，不测显示面板实际出光时间。外部对照每 30 秒采样，不能排除两次样本之间瞬时的系统卡顿。开始/结束截图辅助核对。

模拟器原有 screen_off_timeout=2147483647，测试没有改此值，没有额外唤醒锁；这是亮屏、进程存活条件，不是休眠测试。开始阶段执行了工程检查，资源数据包含这段主机负载，不当作纯空载性能基线。

## 实测结果

观测时长 **3600113 ms（60 分钟）**，121/121 个外部对照样本有效，外部请求失败 0，观测到 61 个不同的成功校时时刻。所有采样均保持目标页前台、应用主页后台和有效校时，实际额外点击 0。绘制遍历计数增加 35410；它不是显示面板刷新帧数。

| 指标（毫秒） | 中位数 | p95 | 最大值 |
| --- | ---: | ---: | ---: |
| 显示相对独立源的绝对估算偏差 | 66 | 116 | 197 |
| 最近绘制距读取时刻 | 48 | 85 | 88 |
| 独立请求 RTT | 98 | 104 | 339 |

121 个样本中绝对估算偏差 >= 1000 ms 的数量为 **0**。显示有符号偏差为 -197～-8 ms，中位 -66 ms；前、后四分之一时段中位分别 -65、-66 ms，没有看到随时长扩大到秒级的趋势。应用最新参考相对独立请求的估算偏差为 -123～+20 ms、中位 -3 ms。采样时校时年龄 330～35716 ms；这里的最大年龄是采样值，不是整个同步周期的上限。

上述偏差依赖 RTT 中点估计，不是绝对 UTC 精度保证。最大 197 ms 样本的独立 RTT 是 339 ms，单该对照的路径不对称不确定度估计即约 170 ms；应用来源请求也有不确定度。不能将 197 ms 宣称为任何网络下的硬上限。

117 次进程外资源采样确认同一进程身份，TOTAL PSS 22544～26377 KiB，末尾 26085 KiB。单核 CPU 区间中位约 4.72%，最大区间 17.25%，包含开始阶段主机工程检查负载及 benchmark 观察器；不是普通发布包的空载基线，也不据此宣称无限运行无泄漏。

## 回归与工程检查

58 个单测失败 0，完整 31 项模拟器功能场景通过。额外故障注入阻塞主线程 2101 ms，期间字符确实冻结，恢复后 250 ms 读取的估算偏差为 -60 ms，零点击；不会把阻塞时长永久累加到计时值。主线程一直阻塞时画面仍会停住，这类暂时卡顿不能由校时消除。

完成与失败状态的浮窗均跟随新参考；任务完成后来源前后跳变不重复点击。后台网络失败后可自动恢复，无需返回主页或手动同步。

标准 JDK 17 / D 盘 Gradle 缓存下，core/app 单测、Debug Lint、Debug 和 R8 Release 构建通过；测量包与独立目标 Lint 通过，普通 Debug/Release manifest 不含测量 Provider/权限。首次整组回归与主机编译并行时，传统连点出现五次手势完成、目标四次 onClick，已保留该失败；停止并行编译后整组重跑通过，最终完整 31 项也通过，没有放宽实际接收断言。

## 走时边界

计算使用绝对锚点与 elapsedRealtime 差值，绘制次数不进入时间计算。七天虚拟时间覆盖快/慢各 200 ppm、每分钟校时，区间内振荡器计算偏差不超过 12 ms；无校时的 200 ppm 虚拟计时器一天会累积 17280 ms，新样本到来后重新归零。这是故障模型，不是本机振荡器精度测量。

| 假设走时偏差 | 一小时不校时的累积 | 60 秒内的累积 |
| --- | ---: | ---: |
| 20 ppm | 72 ms | 1.2 ms |
| 50 ppm | 180 ms | 3 ms |
| 200 ppm | 720 ms | 12 ms |

这些值不含网络授时误差或画面延迟。单调计时避免回调耗时累加，不能创造外部时间真值。[SystemClock](https://developer.android.com/reference/android/os/SystemClock) 的 elapsedRealtime 包含休眠；[Handler](https://developer.android.com/reference/android/os/Handler) 的延迟基于 uptime，休眠会推迟回调。本产品屏幕关闭时停止浮窗/任务，不承诺休眠中刷新或点击。

仍有以下实际限制：

- 未首次成功校时会使用本机时间；长期离线、同步间隔过大、进程被系统终止时，不能保证与来源一致。同步页可查看成功/失败状态，不能只看浮窗毫秒数字判断授时健康。
- 最后五秒的有效定时任务按既有决策固定任务参考；这段短窗口不追逐新来源抖动。完成后必须回到最新参考，不能长期冻结。
- 京东请求 ID 末段时间含义为实测推断，没有公开精度 SLA。网络 RTT 中点有不对称误差；显示普通约每 100 ms 刷新，毫秒格式不等于逐毫秒绘制或 1 ms 精度。
- 有限时长模拟器结果不能保证无限运行、真机功耗管理、重负载或锁屏场景；本轮未连接真机。
