# 悬浮时钟与定时按下精度采集

日期：2026-10-29。用户授权采集两部分的中位数、P95、P99。本轮只改测量工具，不修改生产计时、校时、绘制或点击算法；只用现有模拟器，不提交或推送。

## 固定范围

1. 准入：独立目录备份源码、APK、偏好、服务与设置，固定boot、渲染器、优化APK/hash。先做截图识别与独立请求小样本验证；失败原样保留，不挑选低延迟请求。
2. 时钟：京东OPTIONS来源，应用每60000ms校时；目标页在前台、主应用后台、浮窗持续可见。60分钟，每30秒一个固定时隙，共121个；另有不并入正式分母的预检。每次保存模拟器合成屏幕PNG和设备elapsedRealtimeNanos前后包围，离线从像素读数字，不能用应用字符字段替代。采样前后独立请求，各自保留连接/收发时间、完整关键头、失败，间隔至少1秒。读取应用源锚点/成功时间只是解释校时效果，不回写来源。无Perfetto、高频记录器或旧OnDraw字符串观察器。
3. 点击：同一优化版本、公开滚轮与播放、独立目标实际DOWN/UP/onClick；采用已验证15秒设置预算和4秒提前量。10次预热单列，100次正式测量；另一次20分钟等待任务独立列账，不混入短任务分位数。每任务截止前/接收后各一独立请求，关键区不主动查询UI/资源、不截图、不采栈。保留所有拒绝、缺失、提前和停止；驱动失败停批，不自动重试。
4. 同一AVD不重启、不切渲染器，不在正式采集中构建。时钟组结束后再运行点击组；记录启动年龄，不能将屏幕捕获开销混入点击样本。分段开始/结束的来源锚点与校时年龄用来检查定时同步是否持续生效。

## 统计与判断

- 分开报告：①合成画面数字相对独立同源参考的误差；②内部时间锚点误差；③设定外部时间到真实DOWN的总误差；④内部截止到DOWN/UP/onClick的本地延迟。不可把显示滞后加进点击误差。
- 每项报告有效n、计划n、缺失原因、有符号中位/范围、绝对误差中位/P95/P99/最大、超过50ms数及实际接收率；nearest-rank，不删最大值、不将失败记为0，不合并预热或历史boot。
- 独立请求假设请求ID时间发生在请求期间，形成offset包络；保留前后包络及冲突。不确定度含请求范围、毫秒量化、截图前后包围和参考外推敏感性；不把RTT中点当绝对真值。结果分别为“可确认≤50”“可确认>50”“区间跨50无法确认”。京东时间语义无公开授时SLA，因此结论以同源请求假设为条件。
- P99在n=100/121时只是探索性样本分位，不保证长期每一次；首尾四分位、校时年龄和成功锚点数另列，不把观察不到的间隙说成无卡顿。截图是模拟器合成内容，不等于物理屏幕出光；识别失败/歧义样本保留PNG并拒绝数值判断。
- 截图识别仅使用几何/字体生成模板，不读取应用当前字符或其epoch给图像贴标签；人工核对预检PNG，合成已知字符串、坏格式/噪声测试先行。截图耗时单列，不能把高开销采集宣称为普通运行的完整帧基线。

## 交付与恢复

预检补充：4张真实截图均独立识别成功，三个已知字符串控制通过。首次截图调用1176ms，随后约70～87ms；正式组事前固定一次不入分母的截图预热、等待目标布局就绪，保存预热时间。截图范围仍原样计入，不扣减其耗时；即使最终屏幕50ms无法确认，仍采集完整长时曲线与内部锚点误差，不能用点估计代替区间验收。旧预检失败和4个样本均保留，不并入正式分母。

所有原始请求、PNG、入口回执、工具/source/APK/mapping/hash、协议、失败及结果保留在`.tools/accuracy/<本轮ID>`。结束后标准/对应工具检查、diff检查，恢复本轮备份APK/偏好（启动前后核对）、服务与设置，移除初始不存在的测试包，trace为0。结果和方法写入文档与结构化索引；任何参考或采样能力不足均明确写“无法确认”，不放宽50ms或冒充全部通过。
