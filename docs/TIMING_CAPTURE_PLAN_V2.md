日期：2026-10-28。修订：V2.1，补充端到端、长等待和画面呈现审阅项。状态：仅制定计划，尚未实现本计划新增打点或启动采集。正式采集 manifest 使用 protocolVersion=2.1，不能与旧协议合并为同条件样本。采集阶段冻结生产调度、绘制和授时算法。

## 1. 要回答的问题与范围

本次要区分迟到发生在点击器排队、点击器执行、系统输入、目标处理，还是授时/画面更新；分别判断代码改进空间与设备环境影响。50 ms 保持严格门槛，不能以 P95 达标替代每次达标。

默认执行范围仍是已有 IDEA 内嵌模拟器、独立测试目标和优化构建，不操作真实账户或业务页面。真机对照列为独立阶段，待用户明确扩大本轮范围且设备就绪后执行。缺少真机对照时，“设备限制占多少”保持未完成，不能用模拟器结果替代。不重启内嵌设备、不更换渲染模式来取得较好结果。

“采集完整”指约定场景的时间链路、失败、样本身份和质量记录齐备，不等于所有等待都已归因。无重型采样的基准不能事后恢复调度栈；另一轮诊断不能冒充同一次基准现场。报告必须保留未知项，不能保证一次执行就解释所有自然异常。

## 2. 固定版本、环境和口径

建立不可覆盖的 manifest：源码 SHA-256、两个实际 APK、R8 mapping、脚本、配置、构建工具和事件 schema。正式数据使用唯一 runId；协议修订增加 protocolVersion，旧组保留。禁止边采边改产品算法。

使用 JDK 17、项目 Wrapper、D/E 盘 GRADLE_USER_HOME，不增加生产依赖。记录设备序列号和 boot 身份、系统/ABI、刷新率、分辨率/密度、渲染器、CPU 数、模拟器参数、宿主 CPU/GPU/虚拟化及受测负载；真机另记录温度、电量、充电、省电和网络状态。读不到的值标为 unavailable。

统一使用同设备、同次启动的单调纳秒时间。epoch 只用于来源和显示。MotionEvent 原始事件时间与目标接收时间分列，注明时基和分辨率。通过 Perfetto 时钟映射与已知标记验证跨进程对齐，不能直接混减 uptime、elapsed、主机时间；重启后重新建立映射。

具体约定：app 和目标入口均取 SystemClock.elapsedRealtimeNanos，A 组直接使用共同 boot 时基，不需要 trace 映射。MotionEvent.eventTime/downTime 的兼容基线为 uptime 毫秒，另保留设备可提供的更细事件时间，不冒充接收时刻。每批首尾各取 5 组 elapsed→uptime→elapsed 快照，记录区间而非单点偏移：最小包围间隔需 ≤0.5 ms、含毫秒量化的转换不确定度需 ≤1.5 ms；首尾偏移区间不相容则该批转换失败。B/C 另保存 clock_snapshot 和首尾已知标记，对齐残差需 ≤1 ms。跨 boot 或主时基错误使该批计时质量失败；仅事件时间转换失败时，elapsed 接收指标仍保留，但不能宣称事件时间分解完整。

| 指标 | 定义与边界 |
| --- | --- |
| 派发迟到 | 系统手势接口调用开始 − 最终计划截止；不用创建 timing 对象的时刻代替 |
| DOWN 迟到 | 目标处理 DOWN 的入口 − 最终计划截止；不用 MotionEvent 自带时间代替 |
| onClick 迟到 | 目标 onClick 入口 − 最终计划截止；不是第三方业务或服务器完成 |
| 来源到点击的总误差 | 在派发、DOWN 和 onClick 各入口，用独立来源观测估计该时刻的 epoch，再减用户确认的目标 epoch；带符号值及不确定区间分别保留，不能用本地迟到代替 |
| 本地显示滞后 | 观察时当前参考 − 最近绘制字符对应时间；不是 UTC 误差 |
| 外部显示估算误差 | 绘制字符 − 独立请求中点估计；保留 RTT 区间，不认证请求 ID 精度 |
| 呈现后的画面误差 | 在可关联的实际呈现/观察时刻，所呈现帧的字符时间 − 独立来源估计时间；不把 onDraw、提交或预期呈现时间当实际呈现 |

各组报告 P50/P95/P99、最大值、>50 ms 数量/比例、提前数、实际接收数。P95/P99 使用最近秩；成功样本分布与失败、未执行数分列。1000 个样本的 P99 也不保证未来每次达标，顺序样本不假设独立，任何有效超限不得被平均数覆盖。

### 2.1 端到端参考与误差合成

用户确认目标为 T，最终本地单调截止为 D，某个接收入口的单调时刻为 m。独立参考估计记为 R(m)，则来源到接收总误差为 E(m)=R(m)−T；同时保留本地迟到 L(m)=m−D 与截止映射偏差 R(D)−T。同一固定参考、统一单位下二者可合成总误差；发生参考变化时分段计算，不能相加不同样本的 P95，或因为各分项都 ≤50 ms 就宣布整体 ≤50 ms。

独立观测使用测试驱动的独立工作线程，请求同一京东时间 API；不读取应用锚点作为真值、不写回应用、不共用应用的缓存或连接实例。它只独立于应用估计实现，不是独立授时标准。每次保留 requestId、原始响应头、HTTP 状态、服务端 epoch、单调发送/响应边界、半 RTT、时间戳量化、来源身份及可见缓存信息。接口时间戳代表何时、是否存在缓存和来源系统误差均列为假设/未知；请求 ID 不提供授时 SLA。

R 组及 G 组中，每次任务预注册一次截止前、一次收尾后独立请求：前请求计划在 D−3000 ms 发起，必须在 D−1000 ms 前完成；后请求在关键区结束后的首个可执行时刻发起。实际 D 改变时保留原探针计划，不临时追发；不满足包围、距离或请求条件就标为参考不足。跨任务请求至少间隔 1 秒，可复用已经满足时间条件的独立观测，但必须记录共享 sampleId，不假设样本独立。G 的周期对照保持每 30 秒一次；与事件探针相距不足 1 秒时按预先规则合并，不能突发补发。每个试次冻结 D 的时刻也记录独立参考映射；请求不能进入第 4 节关键区。

先分别以有效的前后观测构造带时间的参考区间，再检验兼容性；不选择 RTT 较小的一条以获得更好结果，不把前后差值平均掉。原始中点估计和假设下的不确定度均保留：网络边界、量化、时基转换及离最近观测的外推误差分列。外推最长 10 秒；外推所用的速率误差上限及依据必须在准入报告固化，没有有效上限、前后区间冲突、缺包或超龄时，不确定度标未知，不能按 0 计算或通过严格门槛。已知 RTT 只提供“服务时间位于请求区间内”假设下的解释区间，不能覆盖来源本身的未知系统偏差。

派发/DOWN/onClick 各报告带符号总误差及区间，不只报告绝对值；总误差区间完全位于 [0,50] ms 才能认定该样本在来源假设下既未提前又迟到不超标。区间完全小于 0 或完全大于 50 ms 标确定越线；区间与 [0,50] 有交集但不被其完整包含时标无法确认，二者都不能用于严格达标。A1/A2 的无外部探针分布只证明本地链路，不能借用 R 组参考补造其端到端误差。

### 2.2 帧与实际呈现的证据

每次绘制保存 frameId、引用的来源 sampleId/任务参考、取时单调时刻与实际字符 epoch、onDraw 入口/出口、刷新请求时刻，以及平台可取得的 VSYNC/帧标识。B/C/P 组另关联时钟浮窗对应图层、提交及实际呈现记录，保存关联规则、丢帧/替换/未呈现状态和关联覆盖率；不能把别的窗口或目标按钮帧当作时钟帧。

按 request→draw、draw→submit、submit→present 和已呈现帧在观察时的年龄分解。需要评价当前可见数字时，取观察时之前最近已呈现且未被替换的时钟帧，不能取当时最新 onDraw。无对应 actual present、跨时基残差不通过或图层归属不明时，呈现指标填 null 加原因，仅保留绘制结论。软件呈现时间不认证手机屏幕像素发光时刻；本轮不增加摄像或光学实验。

E/F 保留原每秒绘制观察，不主动截屏、触发绘制或逐帧访问 UI。P 组验证呈现关联能力与开销；若不能低扰动地把该能力用于整段 E/F，则 E/F 仍只是绘制长期稳定性，P 的短测不能补成 E/F 全程可见精度证据。结论仅覆盖实际观测点，不声称排除两个观测点之间所有瞬时超限。

## 3. 每次任务的必需事件

每条事件含 protocolVersion、runId、batchId、attemptId、进程/线程、事件序号和单调时间。采集前先持久化计划任务清单，进程异常后也能识别缺失终态；点击任务不恢复、不补点。

| 阶段 | 必采内容 |
| --- | --- |
| 前置与播放 | 准备请求起止、窗口就绪、坐标、播放操作起止及是否接受 |
| 真正启用 | arm 事件、来源锚点、目标 epoch、单调截止、启用时实际剩余时间 |
| 重校时 | 样本身份、锚点/RTT/年龄、是否采纳、旧新截止、拒绝原因和锁定时刻 |
| 网络授时 | 每次请求起止、连接返回/响应头取得时刻、成功/失败、原始服务时间、Date/Age、连接是否复用；SDK无法暴露的真实发包时刻标未知，不用 API 边界伪称线上时间 |
| 独立来源对照 | probeId、关联 sampleId、请求原始边界与头、前/后包围关系、外推年龄/假设、参考区间、D 映射偏差、各接收入口总误差和质量原因；不得写回应用 |
| 时钟帧 | frameId、取时/绘制边界、字符 epoch、来源/任务参考、VSYNC/图层/提交/实际呈现标识及关联状态；不支持的字段为 null 加原因 |
| 输入准备 | 计划准备时刻、入队/接受/进入、准星移除起止、最终中心、准备完成 |
| 截止执行 | 到期时刻、回调入队/接受/进入、安全检查起止、点位解析、手势构造起止 |
| 系统调用 | dispatchGesture 调用起止、接受/拒绝/异常、watchdog、完成/取消回调进入 |
| 目标接收 | DOWN/UP/onClick 入口、原始事件时间和 downTime、点位、焦点、任务关联 |
| 终止 | 完成/停止/过期/拒绝/超时/异常/断开，时刻、原因、状态及旧回调是否忽略 |

系统完成回调与目标接收是并行链路，不能预设返回、回调、DOWN、onClick 的统一先后顺序，嵌套阶段不能重复相加。

测量观察器可选，core 仍不依赖 Android。先测试顺序、任务去重、取消后旧回调、同步完成、失败、缺失和时间边界，再接入。普通 Debug/Release 不提供测量控制接口；如果接入改变普通构建代码，须记录差异和开销，不能先声称零开销。

## 4. 失败现场与观测干扰

终止时先保存原始状态、原因和时间，再清理。控件诊断是后续快照，记录起止时间，不能覆盖原始事件。失败分类至少包括：播放未发现/未接受、准备已过期、启用后过期、派发拒绝、系统取消/超时、完成但目标未接收、多次接收、错点、采集器异常。不得统一写成 Did not arm。

用 arm/terminal 事件识别快速完成，不要求稍后的状态读取必须仍为 WAITING。保存有限阶段历史、控件操作、浮窗/选择器/最近反馈、目标焦点和完整触摸回执；终止后截图不能称为原子现场。

最终准备前 500 ms 至引擎和目标均已终止后 500 ms，禁止主动遍历窗口、请求 UI 主线程状态、截图、PSS 或同步写 JSON。目标不返回时，以有界接收超时/停止作为收尾依据，不能无限等待。必需事件先写预分配缓冲，离开关键区后落盘；每次任务都有轻量链路事件，不是有 trace 才打截止点。

测量缓冲初始上限每进程 2 MiB；画面观察复用最近帧记录，不逐帧分配字符串或无限保存日志。溢出、序号缺口、进程异常、未刷盘事件明确标记，不静默覆盖。资源每 30 秒采样、避开关键区；CPU 记录实际区间，PSS 为内存主要指标。

关键区的禁令包括读取应用/目标状态的额外跨进程查询；不阻断产品本来就有的后台周期校时、自然 GC 或系统调度，这些与截止重叠时照实记录。宿主监督与设备驱动心跳只操作独立控制通道，不调用被测进程 UI/Provider 获取状态；独立来源探针、主动资源采样及缓冲落盘在关键区外执行，延误记缺失。常驻驱动、心跳及观测线程的 CPU/内存开销也计入预算，不以“不在 app 内”为由忽略。

### 4.1 设备与运行时归因数据

B/C/P 的配置清单逐项声明是否能取得 CPU frequency/idle、主线程/RenderThread 的 runnable/running/blocked 及唤醒关系、GC/运行时暂停、Binder、图形队列/栅栏和帧时间。保存事件源、采样分辨率、覆盖区间及丢失信息。配置存在但轨迹无数据不算取得；CPU 栈采样不能替代 GC 暂停区间或 GPU 等待证据。不支持某项时登记 unavailable，相关根因保持未知，不为补字段引入生产依赖或更改系统安全策略。

所有正式组由宿主独立采集每秒负载记录，固定包括宿主 CPU 总利用率、模拟器进程 CPU/工作集、可取得的 GPU/磁盘压力；频率/温度/降频和虚拟化调度证据按能力表记录。设备侧每 30 秒资源记录另含可取得的 CPU 频率、温度/节流、电源和网络状态。保存实际采样窗口、跳过原因和最长空档；低频值不能解释单次几十毫秒尖峰。低扰动基准不额外轮询 UI/GC，诊断能力不足不影响其局部延迟事实，但阻止对应设备归因结论。

宿主/设备仅以带双端时间边界的控制消息建立对应区间，复用心跳记录，不直接相减两端时钟。逐段报告对齐不确定度；不能把虚拟机内线程的 running 状态直接当作宿主物理 CPU 正在执行。没有同现场宿主/vCPU 证据时，只能写“与宿主负载同期”或“模拟器环境差异”，不能确认物理 CPU、GPU 或虚拟化是根因。

## 5. 正式采集准入门槛

以下是硬门槛，未通过不能批量采集：

1. 实际安装的非 debuggable 优化包与归档相同；独立目标可采样，停止/失联清理可用，普通包和原偏好已备份。
2. 10 个普通任务均有完整必需事件、唯一终态和可关联的目标回执。时基、跨进程及 trace 对齐通过；缺失为 null 加原因，不能填 0。
3. 独立受控场景覆盖人为主线程阻塞、播放前过期、迟读已完成、拒绝/取消/超时、停止后旧回调及目标未接收。故障注入仅验证观测能力，不混进自然性能分布。
4. 短轨迹具备两个进程的主线程/RenderThread 调度、UI/输入/Binder/帧信息和实际目标调用栈。目标进程运行后建立采样会话；界面启动前与就绪后屏障分列，不能把预热当改善。
5. 有效窗口定义为批次首个前置动作至最后清理终态。每个受测进程至少 20 条带 callsite 的 perf 样本，覆盖率＝该进程窗口内非空 callsite 数/全部 perf 样本数，分母为零即失败。覆盖率需 ≥99%，无展开错误；引用具体窗口还需其线程的实际证据，不能用全轨迹有栈代替某次等待有栈。
6. 严格准入窗口无溢出、perf lost、skipped 或展开错误，info 逐项记录。无法定位到窗口内外的丢失视为可能影响本批；窗口外问题同样归档。质量失败保留，先修配置/协议再用新 ID 验证，有缺口只支持已覆盖事实。
7. 观察器预算预先固定：关键区额外 UI/跨进程查询和同步落盘为 0；预热后固定 5 轮×10000 次记录测试，单次观测 P99 ≤10 微秒，单个关键区累计观测耗时 P95 ≤1 ms。另做模拟截止/失败各 20 次及 3 对开关交错的 60 秒安静时钟，记录分布，单核 CPU 区间中位增量 ≤2 个百分点、每进程 PSS 增量 ≤4 MiB，无缓冲溢出。数值是采集器预算，不是已测结果；波动导致不能评估也不算通过，不挑一对较好数据、不临时放宽预算。
8. 独立来源探针、呈现关联和宿主观察分别做开关对照，沿用第 7 项预算，不合并为零开销。用已知时间轴验证总误差合成、前后参考冲突、超龄/未知外推、总误差提前、各分项通过但总和超限，以及绘制未呈现/帧被替换等分析用例。端到端参考和呈现证据是独立能力门槛；缺少时可以输出 A/B/C 的局部结果，但 R/G 不能宣布端到端达标，P 不能宣布可见精度达标，也不能宣布本计划全部完成。

先固化准入报告与正式矩阵，再开始长批次。这里只允许修测量代码，不顺手优化产品算法。

每类准入最多 3 轮有明确原因的修订验证，仍不通过则停止并报告能力缺口，不无限试到通过。需要改预算或矩阵时先修订协议，不沿用旧组作同条件数据。

## 6. 固定场景矩阵与执行规则

所有点击只作用于独立目标。公开操作流程是主流程；历史 prepareTimed 捷径只作单独复现控制。

先打开浮窗与滚轮，确认窗口/坐标稳定，再计算目标时间、确认并明确播放一次。首次冷界面预留至少 10 秒；稳态设置裕量初始为 3000 ms，烟测若不足，只能在冻结正式协议前统一增大。目标设为“当前来源时间＋设置裕量＋计划播放提前量”；设置完成后用有界等待到计划播放点。计划提前量与真正 arm 时剩余量分列；前置动作迟到则分类记录，不静默重设目标。

播放基准点固定为驱动调用公开播放控件操作的开始时刻，另记操作方式、接受和 app 内 arm；不能混用触摸注入与可访问性 ACTION_CLICK。保存基准点相对计划播放点的偏移。稳态复用同一个已打开的浮窗，冷启动单列；记录设置裕量、来源年龄和实际请求频率，避免关闭/重开导致的额外校时被当成相同条件。若公开滚轮操作无法在预算内可靠完成，准入失败；不能偷偷改走 prepareTimed。

G1/G2/G3/G4 分列 actual arm 剩余时间、全部同步请求/采纳、截止重算次数、旧新截止、最终参考年龄及锁定/准备/接收时刻。G2 及长等待每次须观察到至少一次锁定前采纳更新、临界锁定和单次正确接收，才覆盖完整路径；无更新、失联或过期仍占原名额，不能自动补跑。跨入锁定时已超龄的参考、安全停止和用户取消分别记录，不能为了得到点击放宽产品规则。长等待保持流式落盘和有界缓冲，允许在关键区外刷盘；不把数十分钟全部事件留在 2 MiB 内等待末尾。

H 的 10 类固定为：锁定前来源前移 200 ms、后移 200 ms；锁定后前移 200 ms、后移 200 ms；锁定前校正 1001 ms；更新使剩余时间从锁定外突然进入最后 5 秒；更新使目标已过；来源身份改变；断网后在锁定前恢复；停止后到达旧回调。各类目标和注入时点在准入时固化，保存实际注入时点，不以不准确的驱动唤醒冒充命中边界。5 秒、1000 ms 等精确阈值另用确定性时钟覆盖两侧和等值，实际运行只证明命中的条件。H 只作状态/安全验收，预期停止的场景不要求收到点击，且不得追补。

F 是空闲浮窗长期开启，G 是待执行任务长期开启，两者分别报告，不能因为共用一小时长度而互相替代。R/G 的来源探针和宿主采样也是受测条件的一部分，必须通过开销门槛并单列其影响。

1000 指计划任务数，不是重跑直到 1000 次成功。预注册交错 A1/A2 的顺序；诊断模式使用种子 20261028 生成一次平衡顺序并保存，不重抽。每批首任务保留并单列，首次进程启动与同进程稳态分开。期间不并行编译、其他测试或第二台模拟器；宿主异常负载照实记录，不事后择优删除。

R1/R2 同样交错；G1/G2 各分两个批次，G3/G4 各三轮按固定种子交错，均串行执行，不并行开启任务。G3/G4 每轮独立 arm，只在完成和清理后进入下一项，不把同一次长等待重复计数。长等待预算按实际提前量加准备/回执/清理上限设置；180 秒 trace 上限只适用于短诊断批次，不对 G 截断，也不录制 60 分钟 CPU trace。G 的 1 秒心跳/500 ms 通道监督继续运行，但不以几秒未返回最终点击回执认定长等待超时。

每个新任务有新 attemptId。失败后停止旧任务，确认无待派发、无未闭合触摸，并完成有界清理观察，才执行清单中的下一个独立任务；不是重试。原始事件时间用于发现跨任务迟到/归属不明的回执，不能重置计数后冒充下个任务成功。归属不明、失联或清理超时则停止该批，剩余计未执行；用户停止后不续跑。

固定超时：公开界面准备 15 秒、播放操作返回 3 秒、目标回执至计划截止后 3 秒、停止确认 2 秒、清理确认后安静观察 1 秒；产品原有手势 watchdog 不变。设备外宿主监督者每 500 ms 只检查进程/控制通道，独立于被测 UI。进程死亡、ANR、监督者失联、停止或清理超时均终止本批；停止不能确认时仅在授权测试范围内终止受测应用，不重启设备、不操作其他应用。下一批必须重新准入，不自动恢复原任务。

宿主与独立设备侧驱动每 1 秒交换心跳，连续 5 秒缺失即停止本批并禁止后续任务，设备侧监督不得依赖被测 UI 线程。失联检测和取消有延迟，不能承诺撤回已注入手势或在检测窗内完成的单次任务；这些回执仍须归档。

轨迹覆盖批次首任务前至最后终态后，初始每批最多 180 秒/128 MiB。烟测分别测出设置、等待、清理、屏障开销，预计批次时长和写入量均不得超过上限的一半；即有效预算为 90 秒/64 MiB。包含首尾裕量，超预算则在正式冻结前减小批次、增加批数并更新 manifest，不能环形覆盖或边采边改变条件。无 trace 的批次也按全部阶段最坏预算设置宿主超时；磁盘不足不启动。

新增 G 的计划等待本身约 4 小时 47 分钟，另有 R/P、设置和清理。整套设备占用初估约 12～18 小时/环境，冻结前按烟测给出逐组最坏时间、请求数和空间预算；不是执行承诺。预算不足只能在执行前明确修订协议或报告阶段结果，不能省略长等待后宣布完整。采集器有界等待，不忙等待。独立外部请求按表中频率执行，延误则记缺失，不为填满样本突发补发。

## 7. 真机与设备限制对照

这是回答设备限制问题的必要独立阶段，当前未执行、未扩大授权。获得授权与设备后，使用同一点击器 APK、相同目标和协议，至少重复 A1/A2、R1/R2、E/F、G 和短 B/C/P；单独固化真机矩阵及能力差异。固定刷新率和网络条件，记录无法一致的条件；不同网络差异不能全归 CPU。

比较点击器排队/执行、系统到 DOWN、UP 到 onClick、画面年龄和参考误差。真机尾部明显减小可支持“模拟器环境贡献”，但要区分 CPU、GPU、软件渲染和宿主调度，仍需对应区间证据。单台手机更快不代表所有手机达标，也不证明物理极限。

## 8. 分析、结束标准和交付

先校验数据完整性，再分析。每组分列计划/实际尝试/启用/派发/接收/失败/未执行数，保存分类依据。状态异常和采集器故障分开；脚本失败不等于应用没点击。

台账守恒：计划＝已尝试＋未执行。首个准备动作发出即计已尝试；接收结局互斥为零次、恰好一次正确目标、重复/错点、未知，并与引擎终态、计时结果、数据质量三个独立维度交叉统计。分别报告未接收/已尝试、未执行/计划、正确一次接收/计划及引擎失败/已尝试，不把取消、缺失数据和计时超限重复相加成同一失败率。质量失败仍占原计划名额，不以补采替换；修复后的补采另登记新组和协议关系。必需字段或质量门槛缺失时，该组只能报告部分证据，不能宣布数据包完整。

### 8.1 固定统计拆分与证据覆盖

先按组、提前量、trace/探针模式输出总体和逐批统计，再按以下固定字段拆分；每个子集都附 n、失败/未知数和时间范围，不只给分位数：

- 进程首次启动后的首任务、同进程新开界面、已打开界面的稳态；每批首任务只是批次身份，不能自动称为冷启动。冷启动样本不足时不评价其 P99。
- 任务当前参考在 arm、锁定、接收时的年龄，固定区间 [0,5)、[5,30)、[30,60)、[60,+∞) 秒，以及无有效参考；记录实际同步间隔和截止前最近一次成功/失败同步的距离。
- 是否重算截止、重算次数、修正方向与幅度、是否进入最后 5 秒锁定，以及输入准备前后是否发生 GC/调度/呈现异常；未采到对应证据的组使用 unknown，不能当“没有”。
- F/G 的每 10 分钟时间段及前后段差异；E/P 的每轮；宿主负载使用原始时间序列对照，不按结果挑选“空闲样本”。

分位数仍按最近秩计算，n 很小时可以列出原始排序值，但不得把 3 个长等待结果的最大值包装成稳定 P99。逐批展示 P50/P95/P99、最大值及超限率，报告参考复用与顺序相关性；没有合适的相关性模型时不提供假设样本独立的置信区间，也不将不同条件拼成更大的 n。可视化至少包括阶段耗时分布、误差/来源年龄随时间变化、逐次同步修正、帧绘制至呈现、以及异常现场时间线；CPU 火焰图仅解释有 CPU 采样的组。

每个端到端与呈现指标另报“计划/实际尝试/可评估/确定越线/无法确认/缺失”数量、参考区间宽度/外推年龄及帧关联覆盖率。计时数字存在但参考不足不算可评估；P 组每个预定观察点都要有正确图层实际呈现的关联证据，缺失只保留部分结论。E/F 未关联实际呈现时不得沿用 P 的覆盖率。

每个 >50 ms 样本进入异常清单，拆解截止排队、回调内部、系统到 DOWN、DOWN→UP、UP→onClick；时钟拆参考估计与画面滞后。每类链接最慢十条及全部首任务/失败现场。只在同一次窗口内引用线程状态、唤醒者和实际栈；嵌套 slice 不能重复相加，CPU 火焰图不能当作墙钟等待。

归因分为证据确认、假设待验证、未知。无轨迹基准不能用别轮补造调度原因；自然异常在诊断组未复现时明确写未复现，故障注入不能替代其根因验证。额外采集必须说明缺失项和新假设，保留旧组，不为较好 P99 无限重跑。

性能门槛针对预注册的正常产品组 A1/A2、R1/R2、E/F 和 G；B/C/P 的采样扰动、D 的隔离开关和 H 的故障注入单列，不能用于替代正常组或掩盖失败。与接口对照的估计精度与绝对 UTC 精度分列；HTTP RTT 区间不能界定来源本身的系统误差，未认证来源精度时不能宣布绝对 UTC 的 50 ms 保证。
